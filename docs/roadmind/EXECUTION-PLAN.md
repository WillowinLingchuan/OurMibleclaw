## 一、结论先行

**选题：交通事故辅助研判 —— 把案卷材料排成判责要翻的那份清单**

面向**交警与事故处理民警**：他们不缺法条知识，缺的是**在有限时间里把该看的材料看全**。

### 一句话对比

| | 传统事故处理系统 | 通用法律大模型 / RAG | **交通事故辅助研判智能体 RoadMind** |
|---|---|---|---|
| 输入 | 人工录入的表单 | 一段问题 + 检索到的法条 | **多源案卷材料（陈述 / 勘验 / 车检 / 气象 / 路段）** |
| 输出 | 一张流程单 | 一段法律意见 | **要件对照表 + 争议点清单 + 待补材料清单** |
| 会改主意吗 | ❌ 按流程流转 | ❌ 同样的问法同样的答案 | ✅ **按办结文书的回流修正自己的要件库** |

### 痛点是真实的

- **材料齐不齐，没有人系统性检查**：往往是调解阶段才发现"这一项当初没取证"，而此时现场早没了。
- **要件靠人脑记**：一个民警一年处理几百起，靠经验判断"该看哪几项"；换个人、换个中队，标准就不一样。
- **轻微事故各执一词**：没有行车记录仪、没有目击者，交警到场只能靠刹车痕与双方陈述，材料本身就不全。
- **已有系统能力错位**：现有事故处理平台能录入、能流转、能统计，但**不会告诉你"这案子还缺什么"**。

> **一句话**：现在的系统**能记录，但不能提醒；能统计，但不能发现缺了什么。**

### ⚠️ 这个方向的定位必须说清楚

**本方向刚刚经历过一次大幅收敛**（删掉了疏通调度与出行规划，终点只留在辅助研判）。收敛带来了三个必须一起承担的代价，第十一节与第十三节正面处理，**请读完再做决定**。

## 二、产品定义

### 产品定位

**「交通事故辅助研判智能体 RoadMind」** —— 把散落的案卷材料整合成结构化的证据单元，对照法规要件逐项判定，输出**哪些要件已具备、哪些待确认、还缺什么材料**；并随办结文书的回流，**改写自己的要件库**。

> **名字即功能**：「**交通事故**」是它管的场景，「**辅助研判**」是它的产出（要件对照 / 争议点 / 待补材料），「**智能体**」指它会**按办结文书的回流改写自己的要件库** —— 导航软件永远只会换一条路，它改的是**自己该问什么问题**。
>
> ℹ️ 用「研判」而非「判定」是刻意的：**研判是分析判断过程，不等于认定。** 最终判定始终在交警手里，见第十节红线。

### 特定能力（答辩开场白）

> **在非结构化的案卷材料上，自主完成材料编目 → 要件对照 → 对抗质证 → 追问补齐，输出"哪些要件已具备、哪些待确认、还缺什么材料"的清单；并把办结文书中的认定与说理回流，让下一轮的要件库更贴近法院实际在看的那些要件。**

注意最后半句 —— **"让下一轮更准"才是"特定能力"，"生成一份对照表"只是功能。**

### 输入与输出

| 项 | 内容 |
|---|---|
| **输入** | 当事人陈述、现场勘验记录、车检报告、气象条件、路段属性、（可选）影像材料 |
| **输出** | ① 要件对照表（具备 / 待确认 / 缺失 + 依据证据 ID）② 争议点清单 ③ **待补材料清单** ④ 免责声明（强制） |

> ⚠️ **没有第 ⑤ 项"责任认定"。** 这是设计，不是缺失。

## 三、终点与智能体角色架构

### 唯一的终点：把材料排齐，不给结论

> **不产出"谁的责任"，产出"交警判责要翻的材料，以及还缺哪一页"。**

真正的价值不在法条本身 —— **交警本来就知道"追尾后车全责"**。价值在于：

| 环节 | 传统做法 | 本方案 |
|---|---|---|
| 材料整理 | 人工翻阅、凭经验挑 | **自动编目成证据单元，逐条带来源与可信度** |
| 法规对照 | 人脑记、凭经验 | **拆成要件，逐项对照，每项指向具体证据** |
| 缺什么 | 常常事后才发现 | **显式输出"待补材料清单"** |
| 争议在哪 | 靠脑子过一遍 | **对抗质证 Agent 主动找矛盾** |

> 答辩话术：**"我们不判责，我们把交警判责要翻的材料提前排好了。"**

### 原四大功能的重新锚定：统一成同一种货币 —— 证据

原方案的感知 / 分级 / 气象 / 预警**能力一项没丢**，但定位从"产品功能"降为**证据来源**：

| 原功能 | 去向 | 形态 |
|---|---|---|
| 感知（视觉识别） | A1 的**证据提取器**（工具） | 若做，是 A1 的一个输入通道；不做则纯文本材料 |
| 事件分级 | A2 的**输出维度** | 「事件紧急度分级」→ **「材料齐备度分级」** |
| 气象联动 | **证据源** | 气象实况 / 历史 → 一类证据单元 |
| 风险评估 | A3 的**输出维度** | 「全域风险等级」→ **「争议强度」** |
| 疏通调度 / 出行规划 | **删除** | 已收敛 |

### 智能体角色架构

```
案卷材料 ──→ A1 材料编目 ──→ 证据单元集
                                │
                 A2 要件对照 ←── 要件库（v1）
                   │  ▲            │
      证据缺口回退 ┘  └── A3 对抗质证（目标函数与 A2 相反）
                   │         │
                   └────┬────┘
                        ▼
              要件对照表 + 争议点 + 待补材料
                        │
                  ┌─────┴─────┐
                  ▼           ▼
            人工闸门      追问规划器
            （交警）    （最少问题集，集合覆盖）
                              │
        ★★A4 复盘 ←──── 办结文书（交警认定 / 法院说理）
                   │
                   └──→ 修正要件库 ──→ 回到 A2（闭环）
```

| Agent | 关键说明 |
|---|---|
| **A1 材料编目** | 判定**哪些材料与本案要件相关**；冲突材料并列保留，不擅自取舍 |
| **A2 要件对照** | ★ 主研判。输出**三态对照**，每个结论都要指向具体证据 ID |
| **A3 对抗质证** | ★ **目标函数与 A2 相反** —— 目标是最大化暴露矛盾，不是给出通顺解释 |
| **★★ A4 复盘** | **本方案唯一的"会改主意"组件** |
| 总调度 | **已删除** —— 它的自主决策点是"多事件并发优先级仲裁"，单案研判下不存在 |

> **每个 Agent 的完整设计规格**（职责 / 输入输出 / 工具 / 自主决策点 / 协商机制 / 幻觉抑制三道防线）见 **[`ARCHITECTURE.md`](ARCHITECTURE.md)**。

### ★ 什么时候才配叫 Agent：三问筛选器

**Agent 的数量不是判据，有没有独立的目标函数才是。我们按这个标准筛掉了四个，留下了四个。**

| 三问 | 感知/分级/气象/风险 | A1 | A2 | A3 | A4 |
|---|---|---|---|---|---|
| 有**独立目标函数**吗（不是上游的延续）？ | 否 | 是 | 是 | **是（与 A2 相反）** | **是（跨案件视角）** |
| 输出会**反过来改变上游输入**吗？ | 否 | 否 | 是（决定追问什么） | 是（反驳 A2） | **是（改变全系统的要件库）** |
| 失败时**其他部分仍能工作**吗？ | 是 | 是 | 是 | 是 | 是 |
| **结论** | **工具 / 证据源，不是 Agent** | Agent | Agent | Agent | **Agent** |

> **删掉总调度的话术**：*"我们删掉了总调度 Agent，因为它原来的自主决策点 —— 并发事件优先级 —— 在新的定位下不存在了。留着一个没有决策点的 Agent，是装饰，不是架构。"*

## 四、★ 两处必须修正的设计

### 修正一：研判是**唯一终点**，不是"四项功能之一"

**原构想的错位**：把"事故责任辅助研判"和"疏通调度""危险预警""出行策略"并列为四项功能。**四项并列等于没有重点**，而且研判只是其中一项，做深做浅都不影响作品成立 —— 于是它永远不会被做深。

**修正后**：**只做这一件事，其余全部降为它的输入。** 这样做的收益是双向的：

- 对评委：**一个终点，讲得清、记得住、比得过**；
- 对团队：**4 个人做一件事，能做到 100%** —— 而不是 4 个人做四件事，各停在 40%。

### 修正二：视觉模块是**可选输入通道**，不是承重模块

**原构想的矛盾**：一边写"全部使用模拟输入"，一边说用 YOLO 识别车辆/障碍物。**那输入是模拟的，视觉模块在看什么？**

**修正后的定位**：视觉是 **A1 材料编目的一个可选输入通道**，不是产品能力。

| 路径 | 做法 | 代价 |
|---|---|---|
| **A · 接公开数据集**（有余力时） | 用 UA-DETRAC 等公开数据集做**真实识别**，证明"识别能力真实存在" | 工作量↑，但视觉从装饰变成真实组件 |
| **B · 纯文本材料**（默认） | 案卷材料走文本，视觉整块不接 | **作品完整成立** —— 视觉本就不是承重的 |

> **关键澄清**：**我们缺的是"现场影像接入"，不是"识别能力"。**
> 而且这条路**符合决策标准** —— 视觉失败，作品仍然成立（`core` 依赖里它本来就是可选的）。

## 五、★ 为什么这是智能体而非工作流

**这是评委最会追问的点。自主决策点必须清晰可见。**

### 先做减法：承认单模型在哪些地方更强

不承认这一点，论证就站不住。**在"把案情讲通顺"这件事上，单模型更好。** 我们的多智能体不是为了提升文本质量。

真正的理由是一条**结构性冲突**：

> **单模型存在「叙事连贯性偏好」—— 它倾向于把材料讲成一个通顺的故事，从而主动抹平矛盾证据。而交通事故研判的核心恰恰是矛盾证据。**
>
> **系统内部必须有一个组件的目标函数是「最大化暴露矛盾」，而不是「给出通顺的解释」。这两个目标在生成层面互相冲突，不可能由同一次调用同时最大化。**

**这不是角色扮演**（"一个扮交警一个扮律师" —— 评委一句话就打穿），是**目标函数对抗**。

### 自主决策点

| 内核组件 | 自主决策内容 | 为什么不是工作流 |
|---|---|---|
| **A1 材料编目** | 从非结构化案卷里判定**哪些材料与本案要件相关** | 需要判断，非规则匹配 |
| **A2 要件对照** | 证据 → 要件的归属，以及「具备 / 待确认」的划界 | 跨文档推理，非查表 |
| **追问规划器** | 在「已知证据 vs 待补要件」下求**最少问题集合** | 追问序列是**解出来的**（集合覆盖），不是写死的清单 |
| **A3 对抗质证** | 自行决定攻击 A2 的哪一条结论、构造什么反例 | 需要判断，且**目标函数与 A2 相反** |
| **★★ A4 复盘** | **从跨案件偏差分布中自己归因，新增或改写要件检查项，并能回滚自己的修改** | **会改变自己的行为** ← 最强自主性 |
| **反思校验器** | 引用的证据 ID 不存在 / 要件自相矛盾 → 自动重做 | 检查产出并重做 |
| **人工闸门** | A2↔A3 对抗不收敛时的**仲裁者**；要件库任何修改须人工批准才生效 | 行业现实 + 合规要求；**法律争议不该由机器仲裁** |

> **一句话**：工作流不会改主意，**只有"会根据结果改变自己策略"的系统才是智能体。** ★★A4 复盘 Agent 就是那个东西。

### 三连追问预演（答辩前背下来）

**追问一：「这不就是 RAG 加了个反馈回路？」**
> 普通 RAG 的反馈改的是**排序** —— 同一批文档重新打分。A4 改的是**候选集合本身**：上一轮在 200 条条款里只召回了 30 条，复盘发现法院实际援引的条款中有 8 条不在这 30 条里，**系统把检索面从 30 条扩到 38 条**。这改变了系统的**输入空间**，不只是排序。**改输入空间 ≠ 改排序。**

**追问二：「调参嘛，工作流也能调参。」**
> 区别在两点：① **加哪一条** —— 它要从"法院说理里出现、而我们清单里没有"的要件中**抽象**出一条**可复用**的检查项，这是跨文档归纳，是推理；② **加完之后会不会反悔** —— A4 能**撤销自己此前的修改**，自动加规则的脚本不会。
> 而且工作流里也有人加规则，但**加规则的是人**。这里的区别不是"能不能加"，是**谁发起、谁归因、谁回滚**。

**追问三：「你怎么证明改了之后是变好，而不是随机漂移？」**
> 两个配套实验（**这是本节论证的义务，不是可选项**）：
> ① **稳定性基线** —— 同一版本、同一案件重复运行 5 次，要件集的 Jaccard 相似度必须**高**。**没有稳定性，就没有"改主意"，只有"乱改"。**
> ② **时间切分实验** —— 用早期年份文书建要件库 v1，在**留出年份**上迭代 K 轮，看覆盖完整度随轮次的曲线。

## 六、★ 核心亮点：要件库回流闭环

**这是把「交通事故辅助研判智能体」从 RAG 应用升级为智能体的唯一改造，也是全案最值钱的部分。**

```
新案件 → A1→A2→A3→追问 → 清单输出 → 案件办结 → 文书回流 → A4 归因改写 → 要件库更准
```

### 裁判文书的四重身份（必须区分清楚）

| 身份 | 用的是哪一段 |
|---|---|
| **不是训练集** | 明确**不训练、不微调** —— 这条边界写死在报告里 |
| **知识来源** | 全条款 → 要件拆解，构建**要件库 v1** + 证据-要件映射表 |
| **输入材料** | **事实材料段**（模拟"案卷"） |
| **真值** | **交警认定段 + 法院说理段** |
| **评测集** | 按年份切分的**留出集**，不参与知识构建 |

> **为什么裁判文书是理想的真值**：**法院的"本院认为"就是免费的、由法官写好的"争议焦点标注"。** 它明确告诉你这个案子法院实际在争哪几项要件 —— 这正是 A4 需要的学习信号。

### ★ 「系统改主意」怎么被看见：时间切分 + 同题重做 + 差异并排

| 步 | 动作 | 屏幕 |
|---|---|---|
| 1 | 仅用 T1（早期年份）构建要件库 v1 | — |
| 2 | 取 T2 中一件**从未见过**的真实案件 D，走完整流程 | 清单 v1 |
| 3 | 取 **T2 中除 D 以外**的已结案件喂给 A4 | 思考链显示归因过程 |
| 4 | 要件库 → v2 | 新增项高亮，标注**"触发它的是文书 №XXX"** |
| 5 | **把同一件案件 D 重新走一遍完整流程** | 清单 v2 |
| 6 | **并排 v1 / v2** | 清单从 6 项变 7 项，新增项高亮 |

> **为什么这个演示比仿真更干净**：**变量唯一** —— 同一案件、同一材料、同一套流程，前后两次输出不同，差异**只能**来自系统对自己的修改。
> ⚠️ **演示纪律：D ∉ 复盘所用案件集。** 标准时间留出协议，脚本里断言。

**收尾台词（全场最后一句）**：
> **"各位，系统刚刚给自己加了一条它昨天不会问的问题。导航软件永远不会这么做 —— 它只会换一条路。而我们做的，是一个会因为结果而改变自己的系统。这就是智能体。"**

### A4 的四级动作空间

选哪一级，由 A4 自己判断：

| 层级 | 动作 | 改的是什么 |
|---|---|---|
| L1 | 扩充 / 收缩**候选条款检索面** | 系统的输入空间 |
| L2 | 调整**证据 → 要件的映射权重** | 系统的注意力 |
| **L3** | **新增 / 改写一项要件检查项** | **系统的行为集合** |
| **L4** | **回滚自己此前的修改** | **系统的自我修正** |

> **「会改变自己的行为」的可观测定义**：**改主意的证据，不是它这次答得不一样了（那是随机性），而是它明天面对一个全新的、从未见过的案件时，会多问一个问题。**

## 九、评测体系

**红线怎么绕开**：我们**不评"责任比例判得对不对"**（那是越界，也做不了）；我们评的是 ——
> **系统的材料组织，与交警/法院实际依赖的要件之间，一致性有多高。**

这是**结构一致性**，不是**结论正确性**。合规边界与可评测性是同一件事。

设案件 c：真值要件集 **R(c)** = 从 ②③ 段抽取的实际援引判断依据；系统声明要件集 **S(c)**。

| 维度 | 指标 | 怎么算 |
|---|---|---|
| 材料覆盖 | **要件覆盖完整度** | F1(S,R)，**权重偏向 recall**（见下） |
| 材料覆盖 | **要件缺失率** | 系统**完全没提**的真值要件数 / \|R\| —— 最严重的失败模式，必须单列 |
| 材料覆盖 | 要件定级正确率 | 系统标「具备/待确认」中判定正确的比例 |
| 材料组织 | **条款召回率** | 真值援引条款 ∈ 系统候选集 的比例（直接度量 A4 的 L1 动作） |
| 争议识别 | **争议点命中率** | S 中标「待确认」项 ∩ R 中争议点 / \|R 争议点\| —— **衡量判断力而非查表能力的硬指标** |
| 抗幻觉 | 证据回溯可核验率 | 引用的证据 ID 真实存在于案卷的比例（合规底线，可量化） |
| 对抗质量 | **有效矛盾率** | A3 输出中经人工判定为真矛盾的比例 —— **证明多智能体价值的唯一指标** |
| **★ 学习效果** | **覆盖完整度随轮次提升** | 第 1 轮 vs 第 N 轮 —— **核心指标** |
| 学习效果 | 追问收敛轮次 | 补齐要件所需追问轮数，越少越好 |
| 稳定性 | 同版本重现一致性 | 同案件重复运行的要件集 Jaccard —— **把"改主意"与"随机漂移"分开的前提** |

### ★ 要件覆盖完整度的五态加权（不是简单 F1）

| 状态 | 计分 | 理由 |
|---|---|---|
| 标「具备」且真值具备 | 1.0 | 正确 |
| 标「待确认」且真值确为争议点 | 1.0 | **正确且诚实，满分** |
| 标「待确认」但真值无争议 | 0.5 | 过度谨慎，扣分但远轻于漏 |
| 标「具备」但真值不成立 | 0.3 | 与真值冲突 |
| **完全没提（缺失）** | **0** | **最严重的失败模式** |

> ★ **为什么权重偏向 recall**：**漏一条要件 = 交警少看一条材料；多给一条 = 交警多扫一眼。** 代价不对称。
> 这个理由必须写进报告 —— 它是"为什么不是简单 F1"的答案。

### ★ 三组对照实验（最有说服力的部分）

| 组 | 配置 | 覆盖完整度 | 矛盾发现 | 幻觉引用 |
|---|---|---|---|---|
| **A 基准** | 单次 LLM 调用 + 长上下文塞全部材料 | 低 | **≈ 0** | 有 |
| **B 多 Agent，无复盘** | A1+A2+A3，要件库固定 | 中 | **高** | 低 |
| **C 多 Agent，带回流闭环** | 全量 | **随轮次上升** | 高 | 低 |

> **A vs B 回答「为什么需要多智能体」，B vs C 回答「为什么需要闭环」。**
> **第三行就是全案的价值证明。** 它同时说明：**多智能体本身不产生价值，会学习才产生价值。**

## 十、合规定位与答辩边界（必须背下来）

| # | 议题 | 必须用的表述 |
|---|---|---|
| 1 | **事故研判** | "本系统仅提供**辅助参考意见**，**不具备法律效力**，最终判定由交警完成。" |
| 2 | **数据源** | "原型使用**已公开发布的学术司法数据集、法院主动公开的典型案例通报，以及公开可得的裁判文书数据集**；不涉及任何未公开文书、不涉及个人信息、**不做任何爬取**。" |
| 3 | **不训练** | "**不训练、不微调任何模型**；规则与要件来自公开法条与公开文书。" |
| 4 | **闭环数据** | "闭环在**公开裁判文书的留出集**上验证；真实部署时回流源为**办结案件文书**。" |
| 5 | **不做清单** | ❌ 不做责任认定 ❌ 不接真实交管系统 ❌ 不做责任比例 ❌ 不做调度大屏 ❌ 不训练/微调模型 |

> ★ 第 1 条是**红线**。任何"AI 定责"的暗示都会让项目在合规上失分，而这个失分**完全可以避免** ——
> 改为"要件对照 + 待补材料"后，**表述更准确、信息增量更大、风险归零**。

**另需注意**：裁判文书里的事实是**"法院消化过的二手事实"**，不是原始案卷。**这一点主动写进报告** —— 它恰好说明系统定位在"辅助"而非"替代"：它处理的本就是已被结构化过一次的材料。

### 撞题：主动引用，而不是被动被发现

arXiv:2603.17930（2026-03）用**行车记录仪视频 + 法律多智能体推理**做交通事故责任认定，与本方向方法论接近。**撞题的真正来源不是"智能交通"，是"事故责任认定"** —— 所以差异化不能落在场景上：

| 维度 | 该论文 | 本方案 |
|---|---|---|
| 输入模态 | 行车记录仪视频（单视角） | **多源案卷材料** |
| 输出 | **责任认定**（谁负责） | **要件清单 + 争议点 + 待补材料**（不产出责任） |
| 真值 | 视频标注 | **真实裁判文书**（交警认定 + 法院说理） |
| 闭环 | 无（单次推理） | **要件库随文书演化** |
| 合规姿态 | 直接输出责任 | **主动放弃输出责任** |

> **一句话差异（背下来）**：**"它做的是让 AI 判责，我们做的是让 AI 把判责要用的材料准备齐。它越准越危险，我们越准越有用。"**
>
> **策略：在报告里主动引用这篇工作并写明区别。** 评委如果发现你读过最新竞品，撞题扣分立刻变成加分。**主动撞题和被动的被发现撞题，得分完全不同。**

| **领域知识可得性** | ⚠️ 需外部补课 | ✅ 团队在场 | ⚠️ 需补交规与司法文书体例 |
| **真实用户可得性** | ⚠️ 需找投流团队 | ✅ 同学在身边 | ⚠️ 需找交警/法律从业者 |
| Token 消耗论证 | ✅ 天然黑洞 | ⚠️ 需堆规模 | ⚠️ **收敛后变弱**，靠对抗多轮 + 闭环多轮补 |
| 演示冲击力 | ✅ 素材墙 | ⚠️ 曲线表格 | ✅ **要件对照表 + 前后对比，强** |
| 痛点烈度 | ✅ 70-80% 买量成本 | ⚠️ 中等 | ✅ 强（社会价值） |
| **★ 撞题风险** | ✅ **低** | ⚠️ 中 | 🔴 **高**（来源是"事故责任认定"） |
| 商业落地 | ⚠️ 客户未必是移动云客户 | ✅ 高校是移动云 ToB 客户 | ✅ **司法/交管是移动云 ToG 主战场，且机密推理需求最强** |
| 工作量可控性 | ⚠️ 中 | ✅ 高 | ✅ **高（4 Agent、单终点、免训练）** |

### 一句话定位三个方向

- **BoostForge**：赛道最稳，**数据和资源风险最高**
- **PathPilot**：执行确定性最高，**赛道挂靠待确认**
- **RoadMind**：**终点最清晰、工作量最可控、合规需求最硬**，但**撞题风险最高，且闭环是唯一的一条腿**

### ⚠️ 本次收敛的三个代价（必须一起承担）

| # | 代价 | 说明 |
|---|---|---|
| **一** | **闭环在技术上是可选的，在叙事上是承重的** | 删掉疏通/出行/大屏后只剩一条腿。**闭环失败时，作品"能交付"但"不能赢"** —— 这削弱了"硬核必须可选"这条标准的保护力度 |
| **二** | **赛道挂靠被放大** | 变成纯 ToG/司法辅助，挂靠「智能协同办公」可能比原来**更难**。那封给组委会的邮件优先级**不降反升** |
| **三** | **Token 论证变弱** | 靠对抗多轮 + 闭环多轮 + 批量文书处理补；**A3 对抗质证因此不能砍** |

### 我的建议

1. **先冻结"新增方向"。** 三个方向各有一个"一天到一周"的致命问题，**先把这三个问题回答掉**，答案自己会浮出来。
2. **本方向（RoadMind）的取舍取决于验证清单第 6 项**：如果团队讲不出"和别的作品有什么不同"，**建议放弃**。
3. **不建议三线并行。** 4 人做三个方向，三个都会停在 40% 完成度。你们自己的决策记录写着：**"完成度高的中等作品，永远赢过完成度低的高远作品。"**
