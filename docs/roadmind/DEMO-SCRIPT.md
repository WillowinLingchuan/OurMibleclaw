# 交通事故辅助研判智能体 RoadMind · 现场演示脚本

> 配套文档：[`EXECUTION-PLAN.md`](EXECUTION-PLAN.md)（方案）｜ [`ARCHITECTURE.md`](ARCHITECTURE.md)（智能体架构）｜ [`JUDGMENT-DATA.md`](JUDGMENT-DATA.md)（裁判文书接入）
> 目标时长：**5 分钟**（比赛演示视频 + 现场路演同一套脚本）

---

## 一、演示总览

| 项 | 内容 |
|---|---|
| **总时长** | 5 分钟（场景 1 约 1.8 min，场景 2 约 1.4 min，场景 3 约 1.8 min） |
| **页面** | **研判工作台（左）／Agent 思考链路流（右）** |
| **准备物** | 文书库与要件库已预载、三个场景的案卷材料、案件 D 的两次运行结果 |
| **必须演示的四样** | ① Agent 思考链路（含对抗回边）② **要件对照表输出** ③ **要件库被改写的对比** ④ **视频证据**（从对照表点进视频某一秒） |

### 演示节奏的一句话设计

> **场景 1 证明"会推理，且不越界"，场景 2 证明"敢说不知道"，场景 3 证明"会改主意"。**
> **最有说服力的放最后** —— 观众记住的是结尾。

## 二、场景 1 · 雨天追尾剐蹭（约 1.5 分钟）

**目标：证明系统会推理，且**绝不越界**。**

| 步骤 | 画面 | 台词（要点） |
|---|---|---|
| 输入 | 案卷材料展开：双方陈述、现场勘验记录、**一段行车记录仪视频**、气象（小雨）、路段属性 | "下午三点，二环主路，一起追尾。这是交警手上有的全部东西 —— **包括这段行车记录仪**。" |
| **A1 材料编目** | 思考链路滚出：材料 → **证据单元集**（每条带来源与可信度）；**视频那一路显示抽帧、检测框、跟踪轨迹** | "第一步，把散落的材料编成**一条条带出处的证据**。视频这一路是**自己看出来的** —— 检测到车，跟出轨迹。" |
| **A2 要件对照** | 要件对照表展开，每一条都指向具体证据 ID | **"注意 —— 它没说谁的责任。"** |
| **A3 对抗质证** | 思考链路显示 A3 逐条尝试证伪，A2 回边修正 | "现在它自己跟自己吵一架：**每一条结论都要被反驳一遍**，反驳不掉的才留下。" |
| 视频回溯 | **点对照表里的视频证据 → 播放器跳到碰撞前 1.4 秒，高亮那辆车** | "任何一条结论，**都能点回到视频里的那一秒**。不是它说的，是它看到了让你自己看。" |
| 齐备度 | 输出**部分齐备** + 待补材料清单 | "最后给出的是：**还差哪一份材料。**" |

### ★ 场景 1 的演示重点：要件对照表（停 15 秒）

屏幕展示 A2 的输出：

```
【条款】《道路交通安全法实施条例》第 XX 条
【该条款要件】① 后车未与前车保持安全距离   ② 前车无正当理由急刹
【本案具备】① 具备（E03 勘验：制动痕 12m ｜ E07 视频：碰撞前 1.4s 两车距仍在缩短）
【待确认】  ② 待确认（无前车减速数据 → 建议调取前车行车记录仪）
【争议点】  前车是否急刹
【材料齐备度】部分齐备 —— 建议补充后再作认定
⚠️ 本结果仅供交警参考，不具备法律效力
```

> **一句话台词**：**"我们不判责，我们把交警判责要翻的材料，提前排好了。"**

**停这 15 秒不要说话。** 让评委自己读那三行 —— 读完他们就会明白：**这里面没有"谁的责任"。**

## 三、场景 2 · 证据不足的夜间事故（约 1.5 分钟）

**目标：证明系统敢说"我不知道"。这一段比场景 1 更能证明它不越界。**

| 步骤 | 画面 | 台词（要点） |
|---|---|---|
| 输入 | 一起夜间事故：**没有监控、没有目击者**，只有双方陈述 + 一份刹车痕勘验 | "这次更麻烦 —— 没有监控，没有目击者，两个人各说各的。" |
| **A1 编目** | 3 个证据单元，其中一条标 **`conflict`**（双方陈述互斥） | "它没有挑一个信，**两条都留着，标上『冲突』**。" |
| **A2 对照** | 5 项要件：2 项具备、1 项待确认、**2 项缺失** | **"注意这两项 —— 它说的是『缺失』，不是『没有责任』。"** |
| **A3 对抗** | 有效矛盾 2 条 → **争议强度：高** | "它自己指出：这个案子的争议点很硬。" |
| 输出 | **待补材料清单**：建议调取 XX、建议复勘 XX | "它给出的建议是：**再去补这两样。**" |

### ★ 场景 2 的演示重点：那一句台词

> **"「缺失」和「没有责任」是两个完全不同的词。**
> **这个系统只会说前者。这个区别，就是我们要讲的全部。"**

> **为什么这一段必须演**：评委心里最大的疑虑是"你们是不是在用 AI 判责"。**比起嘴上否认，不如当场演示一个它主动认输的案件。** 一个敢说"我没证据"的系统，没有人会怀疑它在越界。

## 四、★ 场景 3 · 同一案件，重做一遍（约 2 分钟）—— 必须放最后

**目标：证明系统会改主意。这是全场最重要的一段。**

### 演示步骤

| 步 | 画面 | 台词（要点） |
|---|---|---|
| 1 | 要件库 **v1**：12 项要件检查项 | "这是它昨天知道的全部 —— 12 项。" |
| 2 | 案件 D 走完整流程 → **要件对照表 v1** | "这是一起它**从没见过的案子**。" |
| 3 | 取 **T2 中除 D 以外**的 47 件已结案件喂给 **★★A4**，思考链路显示归因过程 | "现在，我们把另外四十七件**已经办结**的案子给它看。" |
| 4 | 要件库 → **v2**：13 项，新增项高亮，旁注**「触发它的是文书 №XXX」** | **"系统自己发现了问题。"** |
| 5 | **把同一件案件 D 重新走一遍** → **要件对照表 v2** | "同一件案子，我们再看一遍。" |
| 6 | **并排 v1 / v2**，新增项高亮 | "多了一项。**它给自己加了一条昨天不会问的问题。**" |

### ★ 收尾台词（全场最后一句，背下来）

> **"各位，系统刚刚给自己加了一条它昨天不会问的问题。**
> **导航软件永远不会这么做 —— 它只会换一条路。**
> **而我们做的，是一个会因为结果而改变自己的系统。这就是智能体。"**

### ⚠️ 演示纪律（脚本里必须断言）

> **案件 D ∉ A4 复盘所用的案件集。**
> 这是标准的时间留出协议。**如果不做这个隔离，评委一句话就能问倒你："你是不是把答案告诉它了？"**
> 脚本里写死断言：`assert demo_case_id not in a4_review_case_ids`

### 为什么这个演示比仿真更干净

**变量唯一** —— 同一案件、同一材料、同一套流程，**前后两次输出不同，差异只能来自系统对自己的修改**。
没有仿真随机性，不用现场等结果，**5 秒跑完**。

> **这段演示的价值**：它用一个**具体的、可视的要件库改写**，回答了评委最会追问的那一问 —— **"为什么这是智能体而不是工作流？"**
> 不要用嘴回答，**用这 20 秒的画面回答。**

## 五、演示前检查清单

| # | 检查项 | 备注 |
|---|---|---|
| 1 | 三个场景的案卷材料已预置、可一键触发 | 不要现场造数据 |
| 1b | **视频文件已本地预置**（不要现场下载/解析），**抽帧与检测结果已缓存** | 现场跑检测 = 灾难 |
| 2 | **Agent 思考链路流可见且滚动流畅**，**含 A2⇄A3 对抗回边** | 这是"多智能体"的唯一可视证据 |
| 3 | 每份输出**强制带免责声明，前端关不掉** | 合规要做进产品，不能只靠嘴说 |
| 4 | 场景 3 的**要件库 v1/v2 对比**能并排显示 | 全场高潮，不能出岔子 |
| 5 | 文书库与要件库已预载，闭环能在 30 秒内跑完一轮 | 现场跑文书处理 = 灾难 |
| 6 | **★ 已确认演示案件 D 不在 A4 复盘所用的案件集里** | **被问倒就全完了** |
| 7 | 断网降级方案 | 大模型 API 不可用时切本地 Ollama |
| 8 | 演示者能**不看稿**说出第四节的收尾台词 | 这是全场的记忆点 |

## 六、答辩话术卡片（打印出来贴在手边）

> ★ **第一张是开场卡。** 如果评委没问，**你也要主动说** —— 这是本方向最重要的一句话。

| 评委可能问 | 一句话回答 |
|---|---|
| **★ AI 能判定事故责任吗？** | "不能，我们也不做。我们输出的是**要件对照和待判断的争议点**，最终认定始终在交警手里 —— 系统里**没有责任认定这个字段**，每一份输出都带免责声明。刚才场景 2 里它主动认输的那两项，就是这个设计的证明。" |
| **为什么要多智能体？单 Agent 不行吗？** | "单 Agent 有个绕不过去的问题：**它倾向于把材料讲成一个通顺的故事，从而抹平矛盾证据。** 而事故研判的核心恰恰是矛盾证据。所以我们必须有一个专门的 Agent，它的目标是**最大化暴露矛盾** —— 这两个目标在生成层面互相冲突，**不可能由同一次调用同时最大化**。这不是角色扮演，是目标函数对抗。" |
| **大模型胡说怎么办？** | "三道防线：① **架构隔离** —— A1 只碰事实、A2 才碰法律，出错能定位到哪一层；② **结构化约束** —— 条款 ID 必须从法条库**动态注入，禁止自造**，每条结论必须能回溯到案卷里的证据编号；③ **对抗验证** —— A3 主动证伪 + 校验器自动重做。**我们连续跑 10 次，幻觉条款 ID 出现 0 次。**" |
| **数据是哪来的？** | "**已公开发布的学术司法数据集、法院主动公开的典型案例通报，以及公开可得的裁判文书数据集。** 不涉及任何未公开文书、不涉及个人信息、**不做任何爬取**。文书里的名字、车牌、住址在进入系统前就已脱敏 —— 报告里我们放了脱敏前后的对照样例。" |
| **你知道 arXiv 上那篇用行车记录仪视频做责任认定的论文吗？** | "知道，2603.17930。**差异恰恰在这里：它做的是让 AI 判责，我们做的是让 AI 把判责要用的材料准备齐。它越准越危险，我们越准越有用。** 而且它没有闭环 —— 我们的要件库会随办结文书演化。" |
| **这个东西能落地吗？** | "能。**司法和交管是移动云的 ToG 主战场**，而且案卷是所有 ToG 场景里数据最敏感的 —— **『材料不能出内网，但我们需要大模型』**，这个需求只有机密推理能解。原型阶段我们用公开文书；真实部署时回流源就是**办结案件的文书** —— 这在真实环境里天然存在。" |
| **视频识别准不准？为什么不用它算车速？** | "检测和跟踪用的是**现成的预训练权重，我们不训练模型** —— 车辆检测和轨迹跟踪本身是成熟能力。但**车速我们不算**：单目视频不标定就算不准，而算出来的数字会被拿去做责任判断，**那正是我们不碰的地方**。视频在这里的作用是**让每条结论能点回画面**，不是给出一个精确数字。" |
| **和已有的办案系统有什么不同？** | "它们**能录入，但不能提醒；能统计，但不能发现缺了什么**。我们最核心的不是识别，是**让每办结一个案子，系统就更清楚下一次该问什么**。" |
