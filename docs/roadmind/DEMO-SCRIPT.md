# 交通疏通决策智能体 RoadMind · 现场演示脚本

> 配套文档：`EXECUTION-PLAN.md`（方案）｜ `ARCHITECTURE.md`（智能体架构）
> 目标时长：**5 分钟**（比赛演示视频 + 现场路演同一套脚本）

## 一、演示总览

| 项 | 内容 |
|---|---|
| **总时长** | 5 分钟（场景 1 约 1.5 min，场景 2 约 1.5 min，场景 3 约 1.5 min，收尾约 0.5 min） |
| **页面** | 治理端大屏（左）／公众端出行页（右）／**Agent 思考链路流（下）** |
| **准备物** | 模拟视频源、SUMO 仿真场景、气象模拟接口、3 套预置场景数据 |
| **必须演示的三样** | ① Agent 思考链路 ② 证据链输出 ③ **规则被改写的对比** |

### 演示节奏的一句话设计

> **场景 1 证明"会推理"，场景 3 证明"会权衡"，场景 2 证明"会改主意"。**
> **最有说服力的放最后** —— 观众记住的是结尾。

## 二、场景 1 · 雨天追尾剐蹭（约 1.5 分钟）

**目标：证明系统会推理，且不越界。**

| 步骤 | 画面 | 台词（要点） |
|---|---|---|
| 输入 | 大屏出现模拟视频流：二环主路两车追尾，占用外侧车道；气象面板显示小雨 | "下午三点，二环主路，一起追尾。" |
| ①感知 | 思考链路滚出：YOLOv8 识别 2 车 → 融合上报与气象 → 结构化事件 | "视觉只做一件事：**找到车、判断占道**。" |
| ②分级 | 输出**紧急** + 展开评分依据（主干道 / 雨天 / 占用车道） | "分级不是拍脑袋，**每一项依据都点得开**。" |
| ③疏导 | 分流方案：后方 500m 转辅路；工单派发给最近巡逻车 | "方案下发，工单同时派出。" |
| ④研判 | 证据链面板展开 | **"注意 —— 它没说谁的责任。"** |
| ⑤预警 | 后方车辆收到"前方 500m 事故，减速慢行" | "同一时刻，后方司机已经收到提示。" |

### ★ 场景 1 的演示重点：证据链（停 15 秒）

屏幕展示 ④ 的输出：

```
【证据链】碰撞前 5s 相对位置与速度变化 ｜ 车道位置 ｜ 路面湿滑程度
【相关条款】《道路交通安全法实施条例》第 XX 条
【条款要件】① 后车未保持安全距离  ② ……
【本案具备】① 具备（轨迹支持）  ② 待确认（无前车减速数据）
【待交警判断】前车是否急刹
⚠️ 本结果仅供交警参考，不具备法律效力
```

> **一句话台词**：**"我们不判责，我们把交警判责要翻的材料，提前排好了。"**

## 三、场景 3 · 大雾天气出行（约 1.5 分钟）

**目标：证明系统会权衡，且把价值判断留给用户。**

| 步骤 | 画面 | 台词（要点） |
|---|---|---|
| 输入 | 公众端输入起点终点；气象显示大雾，能见度 < 200m | "同一天早上，一位司机要出门。" |
| ⑤预警 | 全域风险图：低能见度路段 + 团雾路段 + 事故高发段逐一亮起 | "大雾不是天气，**是路网上的具体风险**。" |
| ⑥出行 | **三套方案并列**：最快（高速，风险高）／最安全（低速主干道，避团雾）／均衡 | "我们不给唯一答案。" |

### ★ 场景 3 的演示重点：三套方案并列（停 15 秒）

> **一句话台词**：**"选哪条路是人的价值判断，不是算法该替人做的决定。系统只负责把每条路的代价算清楚。"**

| 途中 | 前方 5km 新发事故 → 动态重规划并推送变更理由 | "路上情况变了，方案跟着变，并且告诉你**为什么变**。" |

## 四、★ 场景 2 · 车辆抛锚占道（约 1.5 分钟）—— 必须放最后

**目标：证明系统会改主意。这是全场最重要的一段。**

| 步骤 | 画面 | 台词（要点） |
|---|---|---|
| 输入 | 视频流：一辆车静止在路口，双闪开启 | "晚高峰，一个路口，一辆抛锚的车。" |
| ①②③ | 识别 → 判**一般** → 派单拖车 | "系统判为『一般』，派了单。" |
| **结果** | 时间轴快进：**等待拖车 40 分钟**，后方排队蔓延 | "……但它等了四十分钟。后方开始排队。" |
| **★⑦复盘** | 复盘 Agent 启动，思考链路显示诊断过程与**阈值改写动画** | **"系统自己发现了问题。"** |
| **对比** | 屏幕并排：**修改前规则** vs **修改后规则** | "**路口 + 高峰时段的抛锚，从现在起自动升级为『紧急』。**" |

### ★ 收尾台词（全场最后一句，背下来）

> **"各位，系统刚刚改掉了自己的一条规则。**
> **导航软件永远不会这么做 —— 它只会换一条路。**
> **而我们做的，是一个会因为结果而改变自己的系统。这就是智能体。"**

> **这段演示的价值**：它用一个**具体的、可视的规则改写**，回答了评委最会追问的那一问 —— **"为什么这是智能体而不是工作流？"**
> 不要用嘴回答，**用这 20 秒的画面回答。**

## 五、演示前检查清单

| # | 检查项 | 备注 |
|---|---|---|
| 1 | 三个场景数据已预置、可一键触发 | 不要现场造数据 |
| 2 | **Agent 思考链路流可见且滚动流畅** | 这是"多智能体"的唯一可视证据 |
| 3 | ④ 研判输出**每条都带免责声明** | 合规要做进产品，不能只靠嘴说 |
| 4 | 场景 2 的**规则改写前后对比**能并排显示 | 全场高潮，不能出岔子 |
| 5 | SUMO 仿真已预热、闭环能在 30 秒内跑完一轮 | 现场等仿真 = 灾难 |
| 6 | 断网降级方案 | 大模型 API 不可用时切本地 Ollama |
| 7 | 演示者能**不看稿**说出第四节的收尾台词 | 这是全场的记忆点 |

## 六、答辩话术卡片（打印出来贴在手边）

| 评委可能问 | 一句话回答 |
|---|---|
| **AI 能判定事故责任吗？** | "不能，我们也不做。我们输出的是**证据链和待判断的争议点**，最终认定始终在交警手里 —— 系统里每一份输出都带免责声明。" |
| **数据是模拟的，怎么证明有效？** | "视觉能力用**公开数据集**验证，闭环在 **SUMO 仿真器**里跑 —— 都是学术界在用的成熟工具，不是自制模拟器。这一点我们在报告里如实说明了。" |
| **为什么要多智能体？单 Agent 不行吗？** | "单 Agent 能生成方案，**但不能让方案变好**。复盘 Agent 要修改分级和疏导两个不同模块的参数，职责分离才让闭环可落地。" |
| **和已有的智慧交通系统有什么不同？** | "它们**能看见，但不能决断；能算快，但不能算险**。而我们最核心的不是识别，是**让每一次处置成为下一次决策的训练数据**。" |
| **大模型胡说怎么办？** | "三道防线：**架构隔离**（事实查询全走工具层）、**规则约束**（交规规则库硬约束）、**参数抑制**（低 temperature + 结构化输出）。" |
| **这个东西能落地吗？** | "治理端是 ToG，公众端是 ToC，**智慧交通正是移动云的 ToG 主战场**。原型阶段我们用仿真和公开数据，真实部署时回流源是处置系统和交警认定 —— **这两样在真实环境里天然存在**。" |
