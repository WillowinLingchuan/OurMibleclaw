## 一、总体架构：四层

```
┌─────────────────────────────────────────────────────────────┐
│  ④ 交互层                                                     │
│  治理端大屏（指挥中心）  │  公众端出行页  │  Agent 思考链路可视化  │
├─────────────────────────────────────────────────────────────┤
│  ③ 智能体层                                                   │
│  总调度 Agent  ←→  6 个专业 Agent  ←→  ★复盘 Agent★           │
├─────────────────────────────────────────────────────────────┤
│  ② 工具层（Function-call）                                    │
│  天气查询 ｜ 路况查询 ｜ 交规检索 ｜ 路网拓扑 ｜ SUMO 仿真接口 ｜ 工单派发 │
├─────────────────────────────────────────────────────────────┤
│  ① 数据层                                                     │
│  视频流 ｜ 上报事件 ｜ 气象 ｜ 路况 ｜ 公开事故数据集 ｜ 交规规则库      │
└─────────────────────────────────────────────────────────────┘
```

> **说明**：智能体层是"会思考"的部分，工具层是"能动手"的部分，数据层是"看得见"的部分。
> **答辩要点**：把"大模型只做推理编排与文本整理、事实查询全部走工具层"讲清楚 —— 这是抑制幻觉的架构级手段，不是 prompt 技巧。

## 三、Agent 设计规格

### ★ 总调度 Agent

| 项 | 内容 |
|---|---|
| **职责** | 事件分发、Agent 间消息路由、多事件并发时的优先级仲裁 |
| **输入** | 事件流（来自感知 Agent） |
| **输出** | 任务分配、执行顺序 |
| **工具** | — |
| **★ 自主决策点** | **多事件并发时的优先级排序与算力分配** —— 是权衡出来的，不是写死的 |

**决策逻辑示意**：
```
同一时刻 3 个事件：
  A. 主干道追尾（紧急）
  B. 支路抛锚（一般）
  C. 高架团雾预警（预防性）
→ 排序：A > C > B（C 优先级高于 B：预防性预警覆盖车辆数是 B 的 20 倍）
```
> 这个排序**每次都不一样**，取决于实时车流与风险敞口。这就是"不是工作流"的证据。

---

### ① 感知 Agent

| 项 | 内容 |
|---|---|
| **职责** | 视觉 + 上报 + 气象 + 路况多源融合 → 结构化事件 |
| **输入** | 视频帧、上报文本、气象 API、路况 API |
| **输出** | `{类型, 位置, 车道占用, 天气, 车流密度, 置信度}` |
| **工具** | 天气查询、路况查询 |
| **自主决策点** | 多源冲突时的置信度裁决（视频说"有车"、上报说"已清障"→ 取哪个？） |

**模型选型**：YOLOv8 预训练权重（车辆 / 障碍物 / 占道）+ OpenCV 帧处理
**⚠️ 边界**：**只识别位置与占道，不识别责任**。责任相关的一切交给研判 Agent。

---

### ② 分级 Agent

| 项 | 内容 |
|---|---|
| **职责** | 事件分级（轻微 / 一般 / 紧急 / 特级）+ **输出评分依据** |
| **输入** | 结构化事件 |
| **输出** | `{等级, 评分依据, 建议响应时限}` |
| **工具** | 路网拓扑（判断是否主干道/路口） |
| **★ 自主决策点** | 综合多源证据判级，非阈值匹配 |
| **★ 被修正对象** | **复盘 Agent 直接修改本 Agent 的阈值** |

**分级维度**（可解释，答辩必讲）：

| 维度 | 权重示例 |
|---|---|
| 道路等级（主干道 / 支路） | 高 |
| 车道占用比例 | 高 |
| 时段（高峰 / 平峰） | 中 |
| 天气条件 | 中 |
| 当前车流密度 | 中 |
| 是否已有二次事故 | 极高 |

---

### ③ 疏导 Agent

| 项 | 内容 |
|---|---|
| **职责** | 分流方案生成、绕行建议、工单派发 |
| **输入** | 事件 + 等级 + 路网拓扑 |
| **输出** | `{分流方案, 绕行路径, 工单内容, 派发对象}` |
| **工具** | 路网拓扑、工单派发 |
| **★ 自主决策点** | 在路网拓扑约束下**搜索分流组合** —— 组合是解出来的 |
| **★ 被修正对象** | 复盘 Agent 修改分流策略权重 |

**协商回路（进阶加分项）**：疏导 Agent 与预警 Agent 互相沟通迭代 ——
疏导方案会改变车流分布 → 车流分布改变风险等级 → 风险等级反过来要求调整疏导方案。**收敛条件是方案不再变化或达到迭代上限。**

---

### ④ 研判 Agent ★ 定位已修正

| 项 | 内容 |
|---|---|
| **职责** | **证据链整合 + 法规要件对照**（⚠️ **不是判定责任**） |
| **输入** | 行驶轨迹、车道信息、违章记录（如有授权）、气象条件 |
| **输出** | `{证据材料（排序后）, 相关法规条款, 条款要件清单, 本案要件具备情况, 待交警判断的争议点}` |
| **工具** | 交规检索 |
| **自主决策点** | 从原始证据中筛出**与法规要件相关**的部分 |

**输出示例骨架**：
```
【证据链】碰撞前 5s 相对位置与速度变化 / 车道位置 / 路面湿滑程度
【相关条款】《道路交通安全法实施条例》第 XX 条
【该条款要件】① 后车未保持安全距离  ② …… 
【本案具备情况】① 具备（轨迹数据支持） ② 待确认（无前车减速数据）
【待交警判断】前车是否急刹
⚠️ 本结果仅供交警参考，不具备法律效力
```

> **答辩话术**：**"我们不判责，我们把交警判责要翻的材料提前排好了。"**

---

### ⑤ 预警 Agent

| 项 | 内容 |
|---|---|
| **职责** | 静态风险点 + 动态风险 + 气象衍生风险 → 融合分级预警 |
| **输入** | 风险点库、实时事件流、气象 |
| **输出** | `{风险等级, 影响范围, 预警文案, 推送对象}` |
| **工具** | 天气查询、路况查询 |
| **★ 被修正对象** | 复盘 Agent 修改风险点权重（预警过但没出事 → 降权；预警过真出事了 → 升权） |

**三类风险源**：
| 类型 | 例子 | 数据来源 |
|---|---|---|
| 静态 | 弯道、事故高发路段 | 历史事故数据 |
| 动态 | 突发事故、临时占道 | 事件流 |
| 气象衍生 | 雨天路滑、大雾低能见度、路面结冰 | 气象 API + 气象-交通风险映射表 |

---

### ⑥ 出行 Agent

| 项 | 内容 |
|---|---|
| **职责** | 多目标路径规划，输出**多套方案**（最快 / 最安全 / 避堵） |
| **输入** | 用户起点终点 + 全域实时风险 |
| **输出** | 多套方案 + 各自全程风险提示与限速建议 |
| **工具** | 路网拓扑、路况查询、天气查询 |
| **自主决策点** | 风险转交通代价的权重推演 |
| **★ 设计原则** | **价值取向由用户选，系统只做推演** —— 不给"唯一最优解" |

**途中动态更新**：前方新发事故 → 重新规划并推送变更理由。

---

### ★⑦ 复盘 Agent ★ 全案唯一"会改主意"的组件

| 项 | 内容 |
|---|---|
| **职责** | **处置结果回流 → 诊断偏差 → 修正其他 Agent 的策略参数** |
| **输入** | 实际清障耗时、是否二次拥堵、预警点位是否真出事、交警最终认定 |
| **输出** | 参数更新指令（发给 ②③⑤） |
| **工具** | SUMO 仿真接口（比赛环境） |
| **★ 自主决策点** | **会改变自己的行为** ← 最强自主性 |

**三个回流源**：

| # | 回流源 | 真值 | 修正对象 |
|---|---|---|---|
| ① | 处置效率 | 实际清障耗时、是否二次拥堵 | ② 分级阈值、③ 分流权重 |
| ② | 事故真值 | 预警点位**是否真的发生事故** | ⑤ 风险点权重 |
| ③ | 交警认定 | 交警的最终责任认定 | ④ 证据权重（真实部署时） |

**修正示例**（Demo 里要展示的那一段）：
```
事件：路口抛锚，判「一般」
结果：实际等待拖车 40 分钟，造成排队拥堵
诊断：分级偏低 —— 路口 + 高峰时段应升级
修正：②分级 Agent 阈值更新 → 「路口 + 高峰」自动升为「紧急」
```

## 四、Agent 间通信机制

| 项 | 设计 |
|---|---|
| 编排框架 | LangGraph（状态图，支持循环与条件边） / AutoGen（对话式协商） |
| 消息格式 | 结构化 JSON（含 `sender` / `receiver` / `intent` / `payload` / `confidence`） |
| 思考链 | 每个 Agent 输出 **Thought → Action → Observation → Answer**，**全量透传给前端** |
| 协商 | 疏导 ↔ 预警 双向迭代，达到收敛条件或迭代上限即停 |
| 仲裁 | 协商不收敛时由总调度 Agent 裁决 |
| 记忆 | 短期记忆（当前事件上下文）；跨事件仅保留被复盘 Agent 固化下来的参数 |

> **前端要展示的就是这张表的运行态** —— 这是"多智能体"从概念变成可视证据的唯一途径。

## 五、幻觉抑制的三道防线（答辩必讲）

| 防线 | 手段 |
|---|---|
| **① 架构隔离** | 大模型**只做推理编排与文本整理**；所有事实查询（天气/路况/交规/路网）一律走工具层 |
| **② 规则约束** | 交规规则库（JSON 规则表 或 Agentic-RAG 向量库）作为**输出的硬约束**，与检索结果冲突时以规则库为准 |
| **③ 参数抑制** | 调低 temperature；关键输出要求结构化 JSON 而非自由文本 |

> **为什么这三条必须讲**：本方案里大模型要处理的是**法规**与**事故**，幻觉的代价是法律与安全级别的。评委一定会问"大模型胡说怎么办"——**这三道防线就是答案。**
