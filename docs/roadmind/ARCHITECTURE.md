## 一、总体架构：四层

```
┌─────────────────────────────────────────────────────────────┐
│  ④ 交互层                                                     │
│  研判工作台  │  前后对比视图（要件库 v1/v2）  │  Agent 思考链路可视化 │
├─────────────────────────────────────────────────────────────┤
│  ③ 智能体层                                                   │
│  A1 材料编目 → A2 要件对照 ⇄ A3 对抗质证 → ★★A4 复盘 Agent★★   │
│  （编排器：LangGraph 状态图 —— 确定性，不占 Agent 名额）          │
├─────────────────────────────────────────────────────────────┤
│  ② 工具层（Function-call）                                    │
│  法条检索 ｜ 要件库查询 ｜ 文书解析 ｜ 证据校验 ｜ 视觉提取（抽帧→检测→跟踪） │
├─────────────────────────────────────────────────────────────┤
│  ① 数据层                                                     │
│  公开裁判文书 ｜ 法条与司法解释 ｜ 要件库（版本化） ｜ 典型案例通报    │
└─────────────────────────────────────────────────────────────┘
```

> **说明**：智能体层是"会判断"的部分，工具层是"能查证"的部分，数据层是"有依据"的部分。
> **答辩要点**：把"大模型只做推理编排与文本整理、事实与法条全部走工具层"讲清楚 —— 这是抑制幻觉的**架构级手段**，不是 prompt 技巧。

## 三、★ 什么时候才配叫 Agent：三问筛选器

**这是给评委的方法论，比一张大架构图更值钱。**

| 三问 | 感知/分级/气象/风险 | A1 | A2 | A3 | A4 |
|---|---|---|---|---|---|
| 有**独立目标函数**吗（不是上游的延续）？ | 否 | 是 | 是 | **是（与 A2 相反）** | **是（跨案件视角）** |
| 输出会**反过来改变上游输入**吗（双向而非单向流水）？ | 否 | 否 | 是（决定追问什么） | 是（反驳 A2） | **是（改变全系统的要件库）** |
| 它失败时**其他部分仍能工作**吗？ | 是 | 是 | 是 | 是 | 是 |
| **结论** | **工具 / 证据源，不是 Agent** | Agent | Agent | Agent | **Agent** |

> **一句话**：**"Agent 的数量不是判据，有没有独立的目标函数才是。我们按这个标准筛掉了四个，留下了四个。"**

**为什么删掉了总调度**：它原来的自主决策点是"多事件并发时的优先级仲裁"。**单案研判下并发不存在**，这个决策点也就消失了。留着一个没有决策点的 Agent，是装饰，不是架构。

## 四、Agent 设计规格

### A1 材料编目 Agent

| 项 | 内容 |
|---|---|
| **职责** | 把非结构化案卷材料编目成结构化的**证据单元集** |
| **输入** | 当事人陈述、现场勘验记录、车检报告、气象条件、路段属性、（可选）影像材料 |
| **输出** | `[{evidence_id, source, content, timestamp, confidence, conflict_flag}]` |
| **工具** | 文书解析、脱敏、**视觉提取**（视频 → 轨迹 → 证据单元） |
| **自主决策点** | 判定**哪些材料与本案要件相关**（需要判断，非规则匹配）；**冲突材料并列保留**，不擅自取舍 |

**⚠️ 边界（写死）**：**只做事实编目，不做任何法律判断。** 这条边界是幻觉抑制的第一道防线 —— 把"事实"和"法律"分在两个 Agent 里，出错时才知道是哪一层错的。

#### 视觉通道：视频怎么变成证据（P2 负责实现，见 [`TEAM-ROLES.md`](TEAM-ROLES.md) P2 第 2 项）

案卷含影像材料时，走三步把它变成**和其他证据同构的证据单元**：

| 步 | 做什么 | 怎么做 |
|---|---|---|
| 1 | 抽帧 | 每 0.5 秒取一帧 |
| 2 | 车辆检测 | YOLOv8 **预训练权重**（COCO：car / bus / truck / motorcycle / person） |
| 3 | 多目标跟踪 | ByteTrack，把每辆车在各帧的框串成一条**轨迹** |

**输出**：`[{evidence_id, source: "video:XXX@frame1234", content, timestamp, confidence, conflict_flag}]`
—— 与文本材料编出的证据**共用同一套 Schema**，A2 不需要特判。

**从轨迹能得到什么**：

| 得到 | 对应哪条要件 |
|---|---|
| 车辆数、运动方向、碰撞时刻 | 基本事实 |
| 两车距离变化 | 「是否保持安全距离」 |
| 越线 / 占道 | 「是否按规定车道行驶」 |

> ⚠️ **边界**：**不测精确车速与距离** —— 单目视频不标定就算不准，硬做会被评委当场问倒；**不做责任判断**。
> **不训练自定义数据集**，全部用现成权重。
> **这是可选输入通道**：不做它，纯文本案卷照样跑通整套流程 —— **作品完整成立**。

### A2 要件对照 Agent ★ 主研判

| 项 | 内容 |
|---|---|
| **职责** | **证据单元 → 法规要件的逐项对照**（⚠️ **不是判定责任**） |
| **输入** | 证据单元集 + 候选条款集 + **要件库** |
| **输出** | `{clause_id, 要件, 状态（具备/待确认/缺失）, evidence_ids, 待定原因}` |
| **工具** | 条款检索、要件库查询 |
| **自主决策点** | 证据 → 要件的**归属判断**，以及「具备 / 待确认」的划界（跨文档推理，非查表） |
| **★ 被修正对象** | **A4 修改检索面（L1）与要件库（L3）** |

**输出示例骨架**（这就是产品的最终形态）：
```
【条款】《道路交通安全法实施条例》第 XX 条
【该条款要件】① 后车未与前车保持安全距离   ② 前车无正当理由急刹
【本案具备】① 具备（证据 E03：后车制动痕 12m，无减速前兆）
【待确认】  ② 待确认（无前车减速数据 → 建议调取前车行车记录仪）
【争议点】  前车是否急刹
【材料齐备度】部分齐备 —— 建议补充后再作认定
⚠️ 本结果仅供交警参考，不具备法律效力
```

> **答辩话术**：**"我们不判责，我们把交警判责要翻的材料提前排好了。"**

**★ 注意输出里没有"责任认定"。** 这不是缺失，是设计 —— 也正因如此，这个系统**可以被自动评测**：要件齐不齐能对着文书真值算，"判得对不对"不能算也不该算。

#### A2 的输出维度一：材料齐备度分级（原「事件分级」的改造）

| 齐备度 | 判据 | 建议 |
|---|---|---|
| **齐备** | 该条款要件全部具备且有证据支撑 | 可直接进入认定环节 |
| **部分齐备** | 存在"待确认"要件，但关键要件有证据 | 建议补充材料 |
| **不齐备** | 关键要件**完全没有证据支撑** | 不建议在此基础上作认定 |

**评价维度**（可解释，答辩必讲）：条款要件覆盖率 / 关键要件是否缺失 / 证据之间是否冲突 / 证据可信度。

#### A2 的输出维度二：证据缺口回退（**非线性协作的证据**）

A2 发现某要件无任何证据支撑时，**回退到 A1** 要求补充编目，或把缺口交给**追问规划器**。

> **这一条回退环很重要**：它说明系统**不是单向流水线**。工作流只会往下走；这里会往回走。

### A3 对抗质证 Agent ★ 目标函数与 A2 相反

| 项 | 内容 |
|---|---|
| **职责** | **对 A2 的每一条结论做证伪尝试**，主动找矛盾 |
| **输入** | 同一批证据 + A2 的完整结论 |
| **输出** | `[{attack_target, 反例或依据, 矛盾是否成立, 矛盾类型}]` |
| **工具** | 条款检索、证据校验 |
| **★ 自主决策点** | 自行决定**攻击哪一条结论、构造什么反例** —— **目标函数与 A2 相反** |

**⚠️ 为什么这不是"角色扮演"（答辩必答）**

> 单模型存在**叙事连贯性偏好** —— 它倾向于把材料讲成一个通顺的故事，从而**主动抹平矛盾证据**。而交通事故研判的核心恰恰是矛盾证据。
> **"给出通顺的解释"和"最大化暴露矛盾"在生成层面互相冲突，不可能由同一次调用同时最大化。** 所以必须拆成两个 Agent，各自有独立的目标函数。这是**目标函数对抗**，不是"一个扮交警一个扮律师"。

**矛盾类型枚举**（白名单，不可自造）：

| 类型 | 含义 |
|---|---|
| 事实冲突 | 双方陈述互斥，且无第三方证据 |
| 证据冲突 | 车检报告与勘验记录不符 |
| 要件冲突 | 同一份证据同时支持两个互斥要件 |
| 证据缺失 | 某要件无任何证据支撑 |

#### A3 的输出维度：争议强度（原「预警分级」的改造）

| 强度 | 判据 |
|---|---|
| **低** | 0 条有效矛盾 |
| **中** | 1–2 条有效矛盾，且均不涉及关键要件 |
| **高** | 涉及关键要件的有效矛盾，或有效矛盾 ≥ 3 条 |

### ★★ A4 复盘 Agent ★ 全案唯一"会改主意"的组件

| 项 | 内容 |
|---|---|
| **职责** | **从跨案件的偏差分布中自己归因，改写要件库** |
| **输入** | 留出集（T2）的已结案件 —— **事实段作为系统输入，②③段作为真值** —— 以及系统当时的产出 |
| **输出** | 要件库修改指令（L1–L4） |
| **工具** | 要件库读写、覆盖度评测、稳定性校验 |
| **★★ 自主决策点** | **会改变自己的行为** ← 最强自主性 |

**四级动作空间**（选哪一级，由它自己判断）：

| 层级 | 动作 | 改的是什么 |
|---|---|---|
| L1 | 扩充 / 收缩**候选条款检索面**（`top_k`） | 系统的**输入空间** |
| L2 | 调整**证据 → 要件的映射权重** | 系统的**注意力** |
| **L3** | **新增 / 改写一项要件检查项** | 系统的**行为集合** |
| **L4** | **回滚自己此前的修改** | 系统的**自我修正** |

> **"会改变自己的行为"的可观测定义（背下来）**：
> **改主意的证据，不是它这次答得不一样了（那是随机性），而是它明天面对一个全新的、从未见过的案件时，会多问一个问题。**

**修正示例**（Demo 里要展示的那一段）：
```
输入：T2 中 47 件已结案件（★ 不含演示案件 D）
当前：系统在 T2 上的要件覆盖完整度 0.62
归因：法院在 9 件案件里都援引了「让右方来车先行」，而我们的要件库里没有这一项
动作：L3 —— 新增要件检查项「是否违反让右方来车先行规则」
结果：要件库 12 项 → 13 项
评测：覆盖完整度 0.62 → 0.71 ✅   稳定性 Jaccard 0.88 ✅
```

**回滚条件**：修改后若留出集指标下降 → **A4 回滚该次修改**（这本身又是一次判断）。

**⚠️ 裁判文书的四重身份**（见 [`JUDGMENT-DATA.md`](JUDGMENT-DATA.md) 第三章）：**不是训练集**（不训练、不微调）/ 知识来源（构建要件库 v1）/ **输入材料**（事实段）/ **真值**（交警认定段 + 法院说理段）。

### 追问规划器（子模块，**不是 Agent**）

| 项 | 内容 |
|---|---|
| **职责** | 已知证据 vs 待补要件 → **最少追问问题集** |
| **输入** | A2 标为"待确认 / 缺失"的要件 + 已有证据 |
| **输出** | 排好序的最少问题集 + 每个问题能补齐哪些要件 |
| **★ 自主决策点** | 问题集是**解出来的**（集合覆盖问题），不是写死的清单 |

**为什么是集合覆盖**：一个追问常常能同时补齐多个要件（例："前车当时的刹车灯亮了吗" 可同时覆盖"前车是否急刹"与"后车是否有反应时间"）。**排序依据 = 一个问题能补齐的要件数**。

> **这条也是 Token 论证的一部分** —— 追问多轮 = 真实的多轮推理消耗。

---

### 人工闸门

| 项 | 内容 |
|---|---|
| **职责** | ① A2 ↔ A3 对抗**不收敛**时的仲裁者；② **要件库任何修改须人工批准才生效** |
| **输入** | 全部输出 + 不收敛的争议项 + A4 的修改提案 |
| **输出** | 批准 / 驳回 / 仲裁意见 |
| **为什么必须有** | **行业现实 + 合规要求** —— **法律争议不该由机器仲裁**；且要件库变更直接改变系统行为，必须留人审痕迹 |

> ⚠️ **这一行不是走过场。** 答辩时它回答的是"你们凭什么敢让 AI 参与司法流程" —— 答案是：**我们没有让 AI 做决定，我们让 AI 把材料排齐，决定始终在人手里。**

## 五、Agent 间通信机制

| 项 | 设计 |
|---|---|
| 编排框架 | LangGraph（状态图，支持条件边、**对抗回边**与轮次上限） |
| 消息格式 | 结构化 JSON（含 `sender` / `receiver` / `intent` / `payload` / `confidence` / **`evidence_ids`**） |
| 思考链 | 每个 Agent 输出 **Thought → Action → Observation → Answer**，**全量透传给前端** |
| **对抗回路** | A2 → A3 → 若不收敛**回边到 A2**（轮次上限 3）；仍不收敛 → **交人工闸门** |
| **缺口回退** | A2 发现要件无证据支撑 → 回退 A1 补充编目 / 交追问规划器 |
| 记忆 | 短期：当前案件上下文；**跨案件只保留 A4 固化下来的要件库版本** |

> **前端要展示的就是这张表的运行态** —— 这是"多智能体"从概念变成可视证据的唯一途径。
> ⚠️ 特别要展示**对抗回边**：A3 提出反驳 → A2 修正结论，**这一来一回就是"不是工作流"的现场证据。**

## 六、幻觉抑制的三道防线（答辩必讲）

| 防线 | 手段 |
|---|---|
| **① 架构隔离** | 大模型**只做推理编排与文本整理**；所有事实与法条查询（条款 / 要件库 / 证据）一律走工具层。**A1 只碰事实、A2 才碰法律 —— 出错时能定位到是哪一层。** |
| **② 结构化约束** | **条款 ID 必须从法条库动态注入，禁止 LLM 自造**；每条结论必须带 `evidence_ids` 且能回溯到案卷；状态只能取 `具备 / 待确认 / 缺失`（枚举白名单） |
| **③ 对抗验证** | **A3 主动证伪**（本方向独有）+ 反思校验器：引用的证据 ID 不存在 / 要件自相矛盾 → 自动重做 |

> **★ 第 ② 条的核心思想**：**条款 ID 必须动态注入，不能写死** —— 写死的 ID 会在法条修订或案件类型变化时**静默失效**，而且失败得毫无声响。这与原方案里"路口 ID 必须动态注入"是同一条工程原则。

**可量化的验证方式**：连续跑 10 次，**幻觉条款 ID 出现次数应为 0**；**证据回溯可核验率应为 100%**。这两项直接进评测报告。
