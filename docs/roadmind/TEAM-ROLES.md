# RoadMind 分工：谁做什么，做到什么算完

> 一句话版：**P1 找数据定标准 ｜ P2 写后端 ｜ P3 写算法 ｜ P4 写界面**
> **视频识别在 P2 那里** —— 见下面 P2 的第 2 项。

---

## 零、先搞清这个系统长什么样

**它做什么**：把一堆案卷材料，整理成一张「要件对照表」——

```
条款：道路交通安全法实施条例 第 XX 条
  ├ 要件①：后车未与前车保持安全距离   → 具备（证据 E03：制动痕 12 米）
  ├ 要件②：前车无正当理由急刹         → 待确认（没有前车减速数据，建议调行车记录仪）
  └ 结论：材料部分齐备，建议补充后再认定
```

**它不做什么**：不判谁的责任。最终认定始终在交警手里。

**数据怎么流动**：

```
案卷材料 ──► [A1 材料编目] ──► 证据单元
                                  │
                                  ▼
                            [A2 要件对照] ◄──── 要件库（会自己改）
                                  │                 ▲
                                  ▼                 │
                            [A3 对抗质证]           │
                                  │                 │
                                  ▼                 │
                            要件对照表 + 争议点       │
                                  │                 │
                                  ▼                 │
                            办结文书 ──► [A4 复盘] ──┘
```

**四个人的活怎么对应上面这张图**：

| 谁 | 管图中的哪一块 |
|---|---|
| **P1** | 定「要件库」长什么样、定材料怎么切 |
| **P2** | 让整条流水线跑起来（含**把视频变成证据**） |
| **P3** | 做 A3 和 A4（A4 是全案最关键的一块） |
| **P4** | 把结果显示到屏幕上 + 跑评测 |

## 一、P1 · 产品与业务

> **一句话**：你定「什么算一条要件」。全队都按你的标准干活。

### 你要交的 6 样东西

**1. 组委会邮件 —— 周一第一件事就发**
决定这个方向能不能参赛。一天就能发完，不要拖。

**2. 50 份交通事故裁判文书**
从公开数据集或法院公开的典型案例里拿，不爬取。

**3. 切分标准**
一份判决书里，**哪一段给系统看、哪一段是答案**。这份文件是 P2 切分管的唯一依据。
- 输入：你读过的判决书
- 输出：一份文档，写清①事实段 / ②交警认定段 / ③法院说理段的边界特征
- 算完成：P2 照着它写代码，不用再问你

**4. 要件库 v1**
30 条以上高频条款，每条拆成可以逐项核对的「要件」。
- 输出：`clauses/v1.json`
- 算完成：P2 拿到就能直接读，不用再问你格式

**5. 抽检 15 条（事实层）**
要件层那 15 条归 P3。你判「事实有没有被切错」。

**6. 方案报告内容 + 答辩主讲**

### 时间
**前 3 周必须交「切分标准 + 要件库 v1」。** 全队等你这个。

## 二、P2 · 后端

> **一句话**：让数据进得来、让 4 个 Agent 能互相说话。

### 你要交的 6 样东西

---

**1. 文书切分管线**

| | |
|---|---|
| **输入** | 50 份判决书原文（txt / docx / pdf） |
| **输出** | 每份切成 3 段，存成 `corpus/split/{案件号}.json` |
| **算完成** | ① 50 份全跑通不走人工<br>② 跑泄漏扫描脚本，**零命中**<br>③ 人工抽检 30–50 份，确认「交警认定段」里没混进事实段的内容 |

> **⚠️ 这是全案第一号工程风险。** 判决书里的交警认定段经常**物理上就嵌在事实段中间**。切不干净 = 答案泄漏给系统 = 所有指标虚高 = 整套闭环论证作废。
> **这一关不过，不要往下做任何事。**

---

**2. 视频识别模块** ← 就是你在找的那个

**它干什么**：把一段事故现场视频，变成和文字材料**同样格式的证据**。

| | |
|---|---|
| **输入** | 事故视频（行车记录仪 / 路口监控），mp4 |
| **输出** | 证据单元列表，和其他材料编出来的证据**共用同一套 Schema** |

**怎么做（三步，全部用现成权重，不训练）**：

1. **抽帧** —— 每 0.5 秒取一帧
2. **车辆检测** —— YOLOv8 预训练权重（COCO 类别：car / bus / truck / motorcycle / person）
3. **多目标跟踪** —— ByteTrack（ultralytics 自带的），把每辆车在各帧里的框串成一条**轨迹**

**从轨迹能得出什么**（这些就是喂给 A2 的证据）：

| 能得出 | 对应哪条要件 |
|---|---|
| 有几辆车、各往哪个方向走 | 基本事实 |
| 碰撞发生在第几秒 | 基本事实 |
| 两车距离怎么变化 | 「是否保持安全距离」 |
| 有没有车越线、占道 | 「是否按规定车道行驶」 |

**算完成**：
- ① 给 3 段真实视频，能出**轨迹图**
- ② 每条证据都能**定位到视频第几秒**（前端要能跳过去）
- ③ 输出的证据单元能被 A2 当成普通证据用，**不需要特判**

**⚠️ 明确不做的**：
- **不测精确车速、不测精确距离。** 单目视频不标定就算不准，硬做会被评委当场问倒。
- **不做责任判断。**

**退路（重要）**：**这个模块不做，纯文字案卷照样能跑通整套流程，作品完整成立。**
它是加分项，不是承重项 —— 但按你能做到的深度，它是 RoadMind 最有画面感的一块。

---

**3. 编排骨架（LangGraph）**

| | |
|---|---|
| **输入** | 一个案件的证据单元集 + 要件库 |
| **输出** | 一次完整流程跑完的最终对照表 |
| **算完成** | ① 一个案件能从 A1 跑到 A4 再回到 A2<br>② 对抗回边能跑通（A3 反驳 → A2 修正），轮次上限 3<br>③ 有「缺口回退」：A2 发现某要件没证据 → 退回 A1 补编目 |

---

**4. 工具层（4 个 Function-call）**

查法条 ｜ 查要件库 ｜ 解析文书 ｜ 校验证据

**算完成**：Agent 需要法条时**调用工具拿**，不是自己编出来。

---

**5. 护栏校验器**

拦三类错：条款 ID 是编的 ｜ 证据 ID 在案卷里不存在 ｜ 状态值不在白名单（只有「具备 / 待确认 / 缺失」三种）。

**算完成**：连续跑 10 次，**编造的条款 ID 出现 0 次**。

---

**6. 三套接口，W2 周五冻结**

三段切分 Schema ｜ Agent 消息 Schema ｜ 思考链事件流 —— 交出 schema 文件。

> P4 拿不到这些就只能空转。**这一条不准拖。**

## 三、P3 · 算法

> **一句话**：做 A3 和 A4。**A4 是全案唯一「会改主意」的地方。**

### 你要交的 4 样东西

---

**1. A4 复盘 Agent** ← 全案命门

**它干什么**：看一批已经办结的案件，发现「法院实际用了、但我们要件库没有」的东西，然后**改自己的要件库**。

| | |
|---|---|
| **输入** | 留出集里的已办结案件（**事实段给系统看，②③段是答案**）+ 系统当时的输出 |
| **输出** | 要件库的修改指令 |

**它能做 4 种改动，选哪种由它自己判断**：

| | 改什么 |
|---|---|
| L1 | 改「去哪些条款里找」—— 比如上轮只找了 30 条，发现法院引的有一半不在里面，把范围扩到 38 条 |
| L2 | 改「证据和要件的匹配权重」 |
| **L3** | **加一条 / 改一条要件检查项** ← **最关键的一种** |
| L4 | **撤销自己之前的某次修改** |

**算完成（4 条都要满足）**：

| 判据 | 为什么 |
|---|---|
| 迭代 3 轮后，覆盖完整度**确实比第 1 轮高** | 证明它真的在学 |
| 同一案件重复跑 10 次，要件集相似度 **≥ 0.8** | 把「改主意」和「乱改」分开。**没有这条，前面那条不算数** |
| 它能**回滚**自己此前的修改 | 证明不是单向加规则 |
| 它**只改要件库和参数，不改代码** | 证明是自演化，不是人写死的 |

**做到了是什么样**（这就是演示时屏幕上的东西）：
```
输入：47 件已办结案件
当前覆盖完整度：0.62
归因：法院在 9 件案子里都援引了「让右方来车先行」，我们要件库里没这条
动作：L3 —— 新增要件检查项「是否违反让右方来车先行规则」
结果：要件库 12 项 → 13 项
评测：覆盖完整度 0.62 → 0.71    稳定性 0.88 ✓
```

**做不到会怎样**：作品还能交付（A1–A3 仍是一个完整的证据整理工具），但**拿不到最关键那档分**。所以这块的优先级最高。

---

**2. A3 对抗质证策略**

**它干什么**：给 A2 的每一条结论挑毛病。

| | |
|---|---|
| **你要出的** | 矛盾类型枚举（4 类，白名单不许自造）+ 怎么构造反例的逻辑 |
| **算完成** | 给 10 个案件的 A2 输出，A3 能挑出真矛盾（人工判定），并报出**有效矛盾率** |

> **接线归 P2，你只出策略。** 不要自己写编排代码。

---

**3. 追问规划器**

**它干什么**：案子缺证据时，算出「最少问几个问题能补齐」。

| | |
|---|---|
| **算完成** | 给定缺失要件集，输出问题清单，问题数接近理论最少（这是集合覆盖问题） |

---

**4. 评测口径 + 评测报告**

**你要出的**：覆盖完整度怎么算（五态加权）、稳定性怎么算（Jaccard）、三组对照实验怎么设。
**跑批归 P4，解释归你。**

| | |
|---|---|
| **算完成** | 三组对照（单次 LLM / 多 Agent 无复盘 / 多 Agent 带闭环）的结论写出来 |

## 四、P4 · 前端

> **一句话**：把 P2/P3 的东西显示出来，把评测跑出来。

### 你要交的 6 样东西

**1. 评测流水线**
按 P3 定的口径跑批、出曲线。
`算完成`：能跑出「覆盖完整度 vs 迭代轮次」那条曲线。

**2. 研判工作台**
要件对照表，每条要件显示三态（具备 / 待确认 / 缺失），点每条能跳回证据。
`算完成`：三个演示场景能一次走完，**中途不切命令行**。

**3. 前后对比视图**（全场高潮）
要件库 v1 和 v2 并排，新增项高亮，旁边标「触发它的是哪份文书」。
`算完成`：演示场景 3 的 v1/v2 能并排显示。

**4. 视频证据查看器** ← 配合 P2 的视频模块
点一条视频证据，**跳到视频里的对应秒数**并高亮那辆车。
`算完成`：从要件对照表的一条「具备」，能一路点到视频画面。

**5. 思考链可视化**
显示 Agent 的 Thought → Action → Observation，**必须能看到 A2 ⇄ A3 那一来一回**。
`算完成`：答辩时能指着它说「这不是工作流，因为它会往回走」。

**6. 答辩与上架材料成稿**（内容 P1 出，成稿你负责）

> **别把前端排到最后。** 演示冲击力是 RoadMind 相对另两个方向最实在的优势 —— 前后对比视图塌了，答辩就少了最有说服力的 20 秒。
