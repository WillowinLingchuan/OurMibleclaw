## 一、先看这条链：谁卡谁

```
   P1 切分标准 ──► P2 切分管线 ──► P3 A2 接真数据 ──► P4 工作台接真数据
   （W1–W2）        （W1–W3）         （W4）              （W4–W6）
        │                                                    │
        └──────────────────┬─────────────────────────────────┘
                           ▼
                    P3 A4 闭环（W2 设计 → W4 首版 → W7 实验）
                           ▲
                      ★ 全案命门，唯一不能砍的东西
```

> ### ★ 这条链是串联的，任何一环断，后面三个人当场停工。
> **所以本方案的第一原则：不让任何人等。** 等的一方必须有**不依赖上游**的活可干。

**P 编号沿用仓库统一口径**（见 [`../../README.md`](../../README.md)，BoostForge 与 PathPilot 同此）：
**P1 产品+业务 ｜ P2 后端+架构 ｜ P3 算法+核心智能 ｜ P4 前端+全栈** —— 好处是**换方向不换人**。

## 二、本次调整了什么（先说清楚，不同意现在提）

原分工有三处会**真的卡住**，逐条修掉：

| # | 问题 | 调整 |
|---|---|---|
| **1** | **P3 一个人扛 7 项**，还额外背着全案命门（A3 + A4 + 口径 + 基线 + 实验 + 报告） | **把工程性的活全部搬走**：稳定性基线 → P2，覆盖度口径**实现** → P4（P3 只出**定义**，一天的活），A3 的**接线** → P2（P3 只出**策略**）。P3 剩 4 项，**专心做 A4** |
| **2** | **P4 在 W1–W2 完全空转** —— 它要等 P2 冻 Schema 才能写正文 | **把评测流水线交给 P4**。它和 P4 本来就要画的「覆盖度指标曲线」是**同一份代码路径**，拆给两个人做才是浪费 |
| **3** | **P1 前 3 周是全队瓶颈**，却还挂着抽检、报告、PPT、主讲 | **真值抽检拆两半**（P1 抽事实层 15 条，P3 抽要件层 15 条）；**答辩与上架材料主责转 P4**，P1 只出**内容** |

**另外两处明确下来的死线：**

- **组委会邮件 = P1 的周一第一件事**，不许排在「拿数据」之后 —— **它决定这个方向死活**，一天就能发
- **P4 的桩数据契约在 W1 周三冻结** —— 从此 P4 再也不需要等 P2

调整后的负载：**P1 ≈ 7 项 ｜ P2 ≈ 7 项 ｜ P3 4 项（但最难）｜ P4 ≈ 7 项。**
> **P3 项数最少，是故意的** —— 命门不该被杂事挤占。**看着少，做着最重。**

## 三、W1–W2 逐日排期（可执行的核心）

> **这两周是全案的瓶颈期，其余八周都靠它。** 所以只有这两周排到「天」，之后按周。

### W1 —— 目标：数据地基动工，同时**没有一个人在等**

| 谁 | 周一 | 周三 | 周五 | **周五下班前必须交出** |
|---|---|---|---|---|
| **P1** | ★ **发组委会邮件**（赛道挂靠） | 起草切分标准 v0（哪段输入 / 哪段真值） | 合法拿到 ≥50 份文书；切分标准 v1 | **`切分标准 v1` + `corpus/raw/` 有货** |
| **P2** | 建 `corpus/` 目录；写文书解析脚本 | 三段切分器 v0（**先只切 ① 事实段**） | 泄漏扫描脚本 `LEAK_PATTERNS` | **能在 5 份文书上跑通，输出 JSON** |
| **P3** | 通读 10 份判决书，标出 ②③ 段实际位置 | **A4 设计文档**：四级动作空间怎么落地 | A3 矛盾类型枚举（白名单四条） | **`A4 设计 v1`** |
| **P4** | 工作台线框 | ★ **桩数据契约冻结** + 生成桩数据脚本 | 思考链组件（吃桩数据） | **界面能跑起来，不连后端** |

> ★ **P4 的桩数据契约**：约定「假证据 / 假要件长什么样」，与真数据**同一套 Schema**。
> 这一冻结，**P4 从此全程不等 P2** —— 这是本方案里唯一一处刻意的「双轨」。

### W2 —— 目标：**接口冻结**（冻不上，后面全乱）

| 谁 | 交付 |
|---|---|
| **P1** | **切分标准定稿** + **要件库 v1**（≥30 条高频条款，逐条拆成要件） |
| **P2** | ★ **三段切分 Schema 冻结**；切分管线跑通 50 份；**泄漏扫描零命中** |
| **P3** | **覆盖度五态加权定义**（只定义，不实现）+ A4 设计 v2 |
| **P4** | ★ **消息 Schema + 思考链事件流冻结**；评测流水线骨架（吃桩数据出图） |

> ⚠️ **W2 结束时的硬检查**：泄漏扫描零命中 + T1/T2 去重断言通过。
> **不过这一关，W3 不许往下走任何事** —— 切不干净 = 标签泄漏 = 整套闭环指标虚高、论证作废。

## 四、每人手册

### P1 · 队长 / 产品 + 交通业务

> ### 一句话职责：**定义「什么算一条要件」**

**要做的事**
1. ★ **发组委会邮件**（W1 周一，最优先）
2. **拿到数据** —— 合法采集 ≥50 份交通事故裁判文书
3. ★ **定切分标准** —— 哪段是系统输入、哪段是真值；什么算「一条要件」
4. **建要件库 v1** —— ≥30 条高频条款，每条拆成可逐项核对的要件
5. **抽检事实层 15 条**（要件层 15 条归 P3）
6. 方案设计报告内容 + 答辩主讲

**交接物（写死文件名）**

| 交出什么 | 什么时候 | 交给谁 |
|---|---|---|
| 组委会邮件**已发出** | W1 周一 | 全队（结果决定方向死活） |
| `corpus/raw/*.txt` ≥50 份 | W1 周五 | P2 |
| `docs/roadmind/切分标准.md` | W2 周五 | **P2（管线的唯一依据）** |
| `clauses/v1.json` | W2 周五 | P3（A4 的演化起点）、P2（护栏硬约束） |
| 抽检报告（15 条） | W6 | P1 存档，答辩举证 |

**卡点**

| 卡点 | 判据 |
|---|---|
| ★ 切分切得干净吗 | 抽检 **30–50 份**，**泄漏扫描零命中**（全案头号命门） |
| 真值是不是真的 | 抽检 30 条，确认是「**法院真的在用的判断依据**」，不是事实复述 |

**时间**：**前 3 周必须交出「切分标准 + 要件库 v1」**，之后只增补、不重做。

**要补的课**：交规条文、司法文书体例。
> ★ **关键验证**：找懂交规的人确认「要件提炼」成不成立 —— 不成立则 A2 降级或砍掉。

### P2 · 后端 / 架构

> ### 一句话职责：**让文书进得来，让 4 个 Agent 能互相说话**

**要做的事**
1. ★ **文书数据管道** —— 解析 → 三段切分 → 脱敏 → 时间切分与去重 → 泄漏扫描
2. **编排骨架** —— LangGraph 状态图，含**对抗回边**与**缺口回退边**、轮次上限
3. **工具层** —— 查法条 / 查要件库 / 解析文书 / 校验证据，做成 Function-call
4. **护栏校验器** —— 条款 ID 白名单、证据回溯、枚举校验
5. **A3 接线** —— 把 P3 的对抗策略接进编排（**策略归 P3，接线归你**）
6. **稳定性基线** —— 同案件重复跑 N 次算 Jaccard 的跑批工具（P3 用）

**交接物**

| 交出什么 | 什么时候 | 交给谁 |
|---|---|---|
| `corpus/split/*.json` + `corpus/truth/*.json` | W2 | P3 / P4 |
| `contracts/split.schema.json` | **W2 周五冻结** | P1 / P3 / P4 |
| `contracts/message.schema.json` + 思考链事件流 | **W2 周五冻结** | **P4（不冻结，前端只能空转）** |
| 护栏校验器 | W6 | P3 |
| 稳定性跑批工具 | W7 | P3 |

**卡点**

| 卡点 | 判据 |
|---|---|
| ★ 数据管线 | 泄漏扫描零命中 + T1/T2 去重断言通过；一个案件能从 A1 跑到 A4 再回到 A2 |
| 幻觉守得住吗 | 连续跑 10 次，**幻觉条款 ID 出现 0 次** |
| 前端等不等得到 | 两套 Schema **W2 周五必须冻结**，不许拖 |

**时间**：全程；**★ 切分管线是大头，最先做**（原 SUMO 的 6 人天转移到这里，量级相当）。

**要补的课**：LangGraph、中文司法文书解析、向量检索。
> ⚠️ **写死的边界**：**Agent 不许自己拼条款文本**，条款 ID 必须从法条库**动态注入**。见 [`JUDGMENT-DATA.md`](JUDGMENT-DATA.md) 第四节。

### P3 · 算法 / 核心智能

> ### 一句话职责：**全案唯一「会改主意」的地方**

**要做的事（只剩 4 项 —— 故意的）**
1. ★★ **A4 复盘 Agent** —— 从跨案件偏差里自己归因，改写要件库
2. ★ **A3 对抗策略** —— 矛盾类型枚举 + 证伪构造逻辑（**接线归 P2**）
3. **追问规划器** —— 求「最少问几个问题能补齐」的解（集合覆盖）
4. **三组对照实验的解释 + 评测报告**（跑批归 P4，**解释归你**）
5. 抽检**要件层 15 条**

**A4 的四级动作空间（选哪级，它自己判断）**

| 层级 | 动作 | 改的是什么 |
|---|---|---|
| L1 | 扩充 / 收缩候选条款检索面 | 系统的**输入空间** |
| L2 | 调整证据 → 要件的映射权重 | 系统的**注意力** |
| **L3** | **新增 / 改写一项要件检查项** | 系统的**行为集合** |
| **L4** | **回滚自己此前的修改** | 系统的**自我修正** |

**交接物**

| 交出什么 | 什么时候 | 交给谁 |
|---|---|---|
| `A4 设计 v1` | W1 周五 | P2（动作契约） |
| **覆盖度五态加权定义** | W2 周五 | **P4（实现）+ P2** |
| 要件库 Schema（与 P1 共定） | W2 周五 | P2 / P4 |
| **`要件库 v1 / v2 差异数据`** | W8 | **P4 —— 屏幕上最值钱的那张图** |
| 评测报告 | W8 | P1（答辩核心证据） |

**卡点（这是全案的判据，一条都不能松）**

| 卡点 | 判据 |
|---|---|
| ★ 是不是真的在学 | 迭代 3 轮后，覆盖完整度**确实优于第 1 轮** |
| ★ 是「改主意」还是「乱改」 | **稳定性 Jaccard ≥ 0.8** —— 低于这条线，两者分不开 |
| 它敢不敢反悔 | A4 **能回滚**自己此前的修改 |
| 有没有作弊 | **只改要件库与参数，不改代码** |

**时间**：W1 就能开工（A4 设计不需要数据）；A3 紧随切分管线；**A4 全程，W7–W8 收口**。

**要补的课**：集合覆盖 / 贪心近似、Bandit 基础、向量检索调优。
> ⚠️ **A3 不能砍** —— 它不只是学术卖点，**还是 Token 论证的一部分**。真到要砍，砍 A3 保 A4，并在报告里承认 Token 论证变弱。

### P4 · 前端 / 全栈

> ### 一句话职责：**让「它改主意了」在屏幕上被看见，并且把评测跑出来**

**要做的事**
1. ★ **评测流水线** —— 按 P3 的口径跑批、出曲线（**W1 就开工，吃桩数据**）
2. **研判工作台** —— 要件对照表三态（具备 / 待确认 / 缺失），每条指向证据 ID
3. ★ **前后对比视图** —— 要件库 v1 / v2 并排、新增项高亮、旁注触发它的文书编号
4. **思考链可视化** —— Thought → Action → Observation，**必须显示 A2⇄A3 对抗回边**
5. **免责声明** —— 每份输出强制带，**前端关不掉**
6. ★ **答辩与上架材料主责**（内容 P1 出，**成稿归你**）

**交接物**

| 交出什么 | 什么时候 | 交给谁 |
|---|---|---|
| **桩数据契约 + 生成脚本** | **W1 周三冻结** | 自己用（**从此不等 P2**） |
| 评测流水线骨架 | W2 周五 | P3 |
| 工作台（接真数据） | W6 | P1（答辩用） |
| ★ 前后对比视图 | **W8** | P1 |
| AI Store 上架材料 | W10 | 提交 |

**卡点**

| 卡点 | 判据 |
|---|---|
| 三个演示场景能不能一次走完 | **中途不切命令行** |
| 全场高潮出得来吗 | 场景 3 的 **v1 / v2 能并排显示** |

**时间**：W1–W2 用桩数据全部打通（**不等任何人**）；W2 周五拿到冻结 Schema；W4 转真数据。

**要补的课**：Streamlit / Gradio 或 Vue + FastAPI、ECharts。
> ⚠️ **别把它排到最后。** 前端看着「不硬核」，但**演示冲击力是 RoadMind 相对另两个方向的真实优势** —— 前后对比视图是**全场高潮**，它塌了，答辩就少了最有说服力的 20 秒。

## 五、接口冻结表

> **冻结的含义**：格式定死之后双方各自开工，**改格式要两个人一起同意**。

| 冻结点 | 接口 | 谁给谁 | 内容 |
|---|---|---|---|
| **W2 周五** | **★ 三段切分 Schema** | P1 + P2 → P3 / P4 | `case_id / year / split(T1\|T2) / source` + ① 输入段 / ②③ 真值段 |
| **W1 周三** | 桩数据契约 | P4 → P4 | 假证据 / 假要件，**与真数据同一套 Schema** |
| **W2 周五** | 证据单元 Schema | P2 → P3 / P4 | `evidence_id / source / content / timestamp / confidence / conflict_flag` |
| **W2 周五** | Agent 间消息 Schema | P2 → P4 | `sender / receiver / intent / payload / confidence / evidence_ids` |
| **W2 周五** | 思考链事件流 | P2 → P4 | Thought → Action → Observation → Answer |
| **W2 周五** | **★ 要件库 Schema** | P1 → P2 / P3 | `clause_id / 要件清单 / 版本号 / 变更历史`（**必须可回滚**） |
| **W2 周五** | 覆盖度评测口径 | P3 → P4 | 五态加权定义 + 稳定性 Jaccard 算法 |
| **W3 周五** | A4 动作契约 | P3 → P2 | 四级动作（L1–L4）的落盘格式与回滚触发条件 |

> ★ **最要紧的是头两项**：三段切分 Schema（**数据命门**）与要件库 Schema（**技术命门**）。
> **这两个没定，P3 和 P4 都不许开工写正文** —— 但准许用桩数据先跑起来。

## 七、三个风险 + 三条铁律

### 三个风险

| 风险 | 后果 | 对策 |
|---|---|---|
| **★ 数据拿不到** | 整条管线停摆 | 立刻降级到**手工构造 50 例**（一天可完成），**不要卡在这里等** |
| **P2 ↔ P3 强耦合** | 两套 Schema 不清 → 两人互相等 | **W2 周五必须冻结**；冻结前 P3 用桩数据，**不许等** |
| **P1 前 3 周是瓶颈** | 全队等一个人 | 抽检拆半给 P3；答辩材料转 P4；**邮件 W1 周一就发** |

### 三条铁律

1. **不让任何人等** —— 等的一方必须有**不依赖上游**的活；P4 的桩数据契约就是为此存在的
2. **接口先冻结再各自开工** —— 见第五节，**W2 周五是硬线**
3. **P1 的切分标准与要件库 v1 前 3 周必须交付** —— 它们是 A2 的地基与护栏的硬约束
