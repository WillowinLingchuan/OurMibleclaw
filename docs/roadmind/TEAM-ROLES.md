## 一、30 秒看懂

```
                   ┌──────────────────────────────────────┐
   四个人，四条战线，   │  一件事只有一个负责人，不许两个人都在做 │
   互不重叠           └──────────────────────────────────────┘

  P1 ──── 定标准 ──────► 什么算一条要件？哪段是输入、哪段是真值？
         （地基）          交不出切分标准 → 后面三个人的活全起不来

  P2 ──── 修管道 ──────► 文书怎么进来？4 个 Agent 怎么互相说话？
         （管道）          交不出切分管线 → 数据进不来

  P3 ──── 造闭环 ──────► 系统怎么自己改自己的要件库？
         （命门）          交不出 A4 → 作品能交付，但拿不到最关键那档分

  P4 ──── 做界面 ──────► 让「它改主意了」这件事在屏幕上被看见
         （呈现）          交不出前后对比视图 → 全场高潮没了
```

| 角色 | 一句话职责 | **他交不出来，谁最疼** |
|---|---|---|
| **P1 · 队长 / 产品 + 交通业务** | 定义「什么算一条要件」 | P3 的 A2 没有地基 |
| **P2 · 后端 / 架构** | 让文书进得来、让 4 个 Agent 能互相说话 | P1 的数据是死的 |
| **P3 · 算法 / 核心智能** | 全案唯一「会改主意」的地方 | **全案的技术命门** |
| **P4 · 前端 / 全栈** | 让「会改主意」在屏幕上被看见 | 答辩时讲不清 |

> **P 编号是全仓库统一的**（BoostForge / PathPilot 同此口径）：P1 产品+业务 ｜ P2 后端+架构 ｜ P3 算法+核心智能 ｜ P4 前端+全栈。
> **好处：换方向不换人** —— 最终选哪个方向，四个人的角色含义始终一致。

## 二、P1 · 队长 / 产品 + 交通业务

> ### 一句话职责：**定义「什么算一条要件」**

### 要做的事

1. **拿到数据** —— 合法采集 ≥50 份交通事故裁判文书
2. **★ 定切分标准** —— 一份判决书里，哪段是系统输入、哪段是真值；什么算「一条要件」
3. **建要件库 v1** —— ≥30 条高频条款，每条拆解成可逐项核对的要件
4. **人工抽检** —— 拿 30 条真值逐条核对

### 交付物

| 交付物 | 交给谁 | 干什么用 |
|---|---|---|
| ≥50 份文书 | P2 | 建管道的原料 |
| **★ 切分标准** | **P2** | 三段切分管线的**唯一依据** |
| 要件库 v1（JSON） | P2 / P3 | A2 的对照表 + A4 的演化起点 |
| 真值抽检报告 | P1 自己存档 | 答辩时证明数据可靠 |

### 卡点在哪（做不好就卡死下游）

| 卡点 | 判据 |
|---|---|
| **★ 切分切得干净吗** | 抽检 **30–50 份**，**泄漏扫描零命中** —— 这是全案头号命门 |
| **真值是不是真的** | 抽检 30 条，确认是「**法院真的在用的判断依据**」，不是事实复述 |
| **P2 能不能直接读** | 要件库是结构化 JSON，**P2 拿到就能用，不用再来问** |

### 时间：**前 3 周必须交付「切分标准 + 要件库 v1」**

之后只增补、不重做。**这三周要是拖了，P2 和 P3 全在原地等。**

### 要补的课
道路交通法规基础、《道路交通安全法实施条例》条文、司法文书体例（判决书的固定套话）。

> ⚠️ **P1 在这个方向上是全案的根节点，不等人、也不许被等。**
> **★ 关键验证**：找懂交规的人确认「要件提炼」这条路成不成立 —— 不成立则 A2 降级或砍掉。

## 三、P2 · 后端 / 架构

> ### 一句话职责：**让文书进得来，让 4 个 Agent 能互相说话**

### 要做的事

1. **★ 文书数据管道** —— 解析 → **三段切分** → 脱敏 → 时间切分与去重 → 泄漏扫描
2. **编排骨架** —— LangGraph 状态图，含**对抗回边**与**缺口回退边**、轮次上限
3. **工具层** —— 把「查法条 / 查要件库 / 解析文书 / 校验证据」做成 Function-call
4. **护栏校验器** —— 条款 ID 白名单、证据回溯、枚举校验
5. **评测流水线** —— 跑得动 P3 定的口径

### 交付物

| 交付物 | 交给谁 | 干什么用 |
|---|---|---|
| **★ 三段切分管线** | P3 / P4 | `corpus/split/` 与 `corpus/truth/` 数据 |
| Agent 间消息 Schema | **P4** | **不冻结，前端只能空转** |
| 思考链事件流 | **P4** | 屏幕上那条滚动的链路 |
| 护栏校验器 | P3 | 挡住幻觉条款 ID |

### 卡点在哪

| 卡点 | 判据 |
|---|---|
| **★ 数据管线** | **泄漏扫描零命中 + T1/T2 去重断言通过**，且一个案件能从 A1 跑到 A4 再回到 A2 |
| **幻觉守得住吗** | 连续跑 10 次，**幻觉条款 ID 出现 0 次** |
| **前端等不等得到** | 两套 Schema 第 1 周末必须冻结 |

### 时间：**全程；★ 切分管线是大头，最先做**

> 这是原方案里 SUMO 接入的 6 人天**转移过来的**位置，量级相当 —— **它不是配角，是新的主力工程。**

### 要补的课
LangGraph、中文司法文书解析、向量检索。

### ⚠️ 一条写死的边界
**Agent 不许自己拼条款文本。** 条款 ID 必须从法条库**动态注入** —— 写死的 ID 会在法条修订或案件类型变化时**静默失效**。见 [`JUDGMENT-DATA.md`](JUDGMENT-DATA.md) 第四节。

## 四、P3 · 算法 / 核心智能

> ### 一句话职责：**全案唯一「会改主意」的地方**

### 要做的事

1. **★★ A4 复盘 Agent** —— 从跨案件的偏差里自己归因，改写要件库
2. **A3 对抗质证 Agent** —— 专门挑 A2 的毛病
3. **追问规划器** —— 求「最少问几个问题就能补齐」的解
4. **评测口径** —— 覆盖完整度五态加权 + 稳定性基线
5. **三组对照实验** —— 用数据回答「为什么要多智能体」「为什么要闭环」

### A4 的四级动作空间（选哪级，它自己判断）

| 层级 | 动作 | 改的是什么 |
|---|---|---|
| L1 | 扩充 / 收缩候选条款检索面 | 系统的**输入空间** |
| L2 | 调整证据 → 要件的映射权重 | 系统的**注意力** |
| **L3** | **新增 / 改写一项要件检查项** | 系统的**行为集合** |
| **L4** | **回滚自己此前的修改** | 系统的**自我修正** |

### 交付物

| 交付物 | 交给谁 | 干什么用 |
|---|---|---|
| ★★ A4 演化策略 | — | **全案命门** |
| A3 对抗策略 | P2 | 编排里的对抗回边 |
| **要件库 v1 / v2 差异数据** | **P4** | **屏幕上最值钱的那张图** |
| 三组对照实验 + 评测报告 | P1 | 答辩的核心证据 |

### 卡点在哪

| 卡点 | 判据 |
|---|---|
| **★ 是不是真的在学** | 迭代 3 轮后，覆盖完整度**确实优于第 1 轮** |
| **★ 是「改主意」还是「乱改」** | **稳定性 Jaccard ≥ 0.8** —— 低于这条线，两者就分不开 |
| **它敢不敢反悔** | A4 **能回滚**自己此前的修改 |
| **有没有作弊** | **只改要件库与参数，不改代码** |

### 时间：A3 紧随切分管线之后；A4 全程，最后两周收口

> ⚠️ **A3 不能砍** —— 它不只是学术卖点，**还是 Token 论证的一部分**。
> 若时间不够，砍 A3 保 A4，但要在报告里承认 Token 论证因此变弱。

### 要补的课
集合覆盖 / 贪心近似、Bandit 基础、向量检索调优。

## 五、P4 · 前端 / 全栈

> ### 一句话职责：**让「它改主意了」这件事在屏幕上被看见**

### 要做的事

1. **研判工作台** —— 要件对照表，三态（具备 / 待确认 / 缺失），每条指向证据 ID
2. **★ 前后对比视图** —— 要件库 v1 / v2 并排、新增项高亮、旁注触发它的文书编号
3. **思考链可视化** —— Thought → Action → Observation，**必须显示 A2⇄A3 对抗回边**
4. **免责声明** —— 每份输出强制带上，**前端关不掉**
5. AI Store 上架材料

### 卡点在哪

| 卡点 | 判据 |
|---|---|
| **三个演示场景能不能一次走完** | **中途不切命令行** |
| **全场高潮出得来吗** | 场景 3 的 **v1 / v2 能并排显示** |

### 时间
**前 2 周只做线框 + 假数据**；Schema 冻结后转真数据。

### 要补的课
Streamlit / Gradio 或 Vue + FastAPI、ECharts。

> ⚠️ **最容易被挤压，但别把它排到最后。**
> 前端看着「不硬核」，可是**演示冲击力是 RoadMind 相对另两个方向的真实优势** ——
> 这一版把「前后对比视图」做成了**全场高潮**，它塌了，答辩就少了最有说服力的 20 秒。

## 六、接口冻结表

> **冻结的含义**：格式定死之后双方各自开工，**改格式要两个人一起同意**。

| 冻结点 | 接口 | 谁给谁 | 内容 |
|---|---|---|---|
| **第 1 周末** | **★ 三段切分 Schema** | P1 + P2 → P3 / P4 | `case_id / year / split(T1\|T2) / source` + ① 输入段 / ②③ 真值段 |
| **第 1 周末** | 证据单元 Schema | P2 → P3 / P4 | `evidence_id / source / content / timestamp / confidence / conflict_flag` |
| **第 1 周末** | Agent 间消息 Schema | P2 → P4 | `sender / receiver / intent / payload / confidence / evidence_ids` |
| **第 1 周末** | 思考链事件流 | P2 → P4 | Thought → Action → Observation → Answer |
| **第 2 周末** | **★ 要件库 Schema** | P1 → P2 / P3 | `clause_id / 要件清单 / 版本号 / 变更历史`（**必须可回滚**） |
| **第 2 周末** | 覆盖度评测口径 | P3 → P2 / P4 | 五态加权定义 + 稳定性 Jaccard 算法 |
| **第 3 周末** | A4 动作契约 | P3 → P2 | 四级动作（L1–L4）的落盘格式与回滚触发条件 |

> ★ **最要紧的是头两项** —— 三段切分 Schema 对应**数据命门**，要件库 Schema 对应**技术命门**。
> **这两个没定，P3 和 P4 都不许开工写正文**（先用桩数据）。

## 八、三个风险 + 三条铁律

### 三个风险

| 风险 | 后果 | 对策 |
|---|---|---|
| **P3 是单点瓶颈** | A3 + A4 + 评测压在一个人身上 | A3 先行、A4 穿插；**砍 A3 保 A4**（并承认 Token 论证变弱） |
| **P2 ↔ P3 强耦合** | 两套 Schema 不清 → 两人互相等 | **第 2 周末必须冻结**；冻结前 P3 用桩数据，**不许等** |
| **★ 数据拿不到** | 整条管线停摆 | 立刻降级到**手工构造 50 例**（一天可完成），**不要卡在这里等** |

### 三条铁律

1. **P2 与 P3 最先动工** —— 切分管线（数据命门）与 A4 闭环（技术命门）是同一件事的两端，**都是硬阻塞**
2. **接口先冻结再各自开工** —— 前两项（三段切分 Schema / 要件库 Schema）最关键，见第六节
3. **P1 的切分标准与要件库 v1 前 3 周必须交付** —— 它们是 A2 的地基与护栏的硬约束
