# RoadMind · 可行性核定（FEASIBILITY REVIEW）

> 版本：v1.0（2026-09-26）
> 核定对象：**4 人 × 11 天**，从零实现「真实行车记录仪视频识别 + 多智能体责任判定 + 应急方案 + Web 双端」的参赛方案。
> 结论先行：**作为参赛 Demo"能交付、能演示"可行；作为高精度交警辅助工具，11 天不可行。** 必须砍/降级"真实视频精准识别"这一环，其余成立。

---

## 1. 一句话结论

**整体可行（6/10），但只有在你接受以下三个取舍时才可行：**

1. 视频识别 = **关键帧抽帧 + 本地检测（作为辅助）**，不追求高精度，允许手动/文字补录兜底；
2. 责任判定定位为 **"辅助参考 + 置信度提示"**，不承诺让交警直接采信；
3. 11 天交付的是 **"闭环能跑的 Demo"**，不是生产级系统。

若坚持"真实行车记录仪视频高精度识别 + 据此精准判责"，**可行性降至 3/10，强烈不建议**。

---

## 3. 最大风险：M1 真实视频精准识别

### 3.1 为什么它几乎不可行（11 天）

- **数据获取难**：真实行车记录仪**事故**视频稀缺，公开、可用、授权清晰的数据集非常少；事故视频还涉及当事人隐私与证据敏感性。
- **精度不达标**：夜间/逆光/遮挡/复杂路口的检测和轨迹重建，仅靠 11 天调不好，检测出错 → 责任判定跟着错 → 连锁放大。
- **责任判定不可验证**：交警判责依赖多源证据（现场照片、证词、痕迹），仅凭单摄像头视频，本来就不充分。

### 3.2 因此必须做的事（降级，对齐"硬核可选"原则）

| 原方案 | 降级方案 | 效果 |
|--------|----------|------|
| 全帧实时识别 | **关键帧抽帧** + 本地检测（YOLO） | 成本/精度可控 |
| 视频是关键输入 | 视频为**可选增强**，文本/手动补录为**主输入** | 无视频也能完整演示 |
| 高精度判责 | 输出**责任建议 + 置信度 + 理由**，标注"辅助" | 逻辑自洽，不怕被挑战 |
| 需要真实事故视频 | 用**公开/合成演示视频** + 预设 demo 数据 | 演示可控、不涉隐私 |

> 落地：M1 从"必做核心"降为"可选增强"。即使视觉识别完全失效，靠**文字描述现场要素 → 责任判定 → 应急方案 → 双端界面** 仍是一个完整、可答辩的智能体作品。

## 4. 11 天资源可行性

- **4 人 × 11 天 ≈ 44 人日**。上表把 M1 降级后，主体工作量（RAG+判定+应急+编排+双端）约 35–40 人日，**勉强够，但无冗余**。
- **技能栈要求**：P3 需会 YOLO/追踪（或愿当天补），P2 需会 LangGraph/FastAPI，P4 需会 Vue/React。任一人不熟会挤压排期。
- **建议**：若 P3 对 CV 不熟，**立即放弃视频识别，改纯文本/图传输入**，把省下的人力投入判定质量与前端完成度——这更符合"完成度高的中等作品赢过完成度低的高远作品"。

---

## 5. 最终建议（务实路线）

**推荐采用【视频可选 + 文本主输入】的降级版落地：**

1. **主流程（必保）**：上传事故照片/文字描述 → 责任判定智能体（RAG 法规+案例）→ 应急方案 → 双端界面。**这是作品的地基，务必 100% 完成。**
2. **增强流程（有余力再做）**：视频抽帧检测，叠加到界面作"感知增强"展示。做不出就砍，不影响主体。
3. **演示策略**：用 1–2 段公开演示视频 + 预设 demo 数据，预先把结果跑好，现场给"输入→过程→结果"的可视化，稳定可控。

> 一句话：**11 天做"视频精准识别判责"不现实，但做"多智能体事故辅助研判 + 应急 + 双端"完全可行。** 把重头押在后者，视频作为锦上添花。
