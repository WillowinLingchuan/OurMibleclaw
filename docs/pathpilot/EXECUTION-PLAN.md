# 「知途 PathPilot」执行方案

> 校园学业与综测路径规划智能体 —— 把学校制度文本变成每个学生的可执行路径，并让这条路越走越准
> 面向：第五届「移动云杯」智算应用创新大赛 · **模型应用赛**（挂靠 **智能协同办公** 场景） ｜ 基于 MoMA 平台 ｜ 团队 4 人
> 状态：**候选方向 · 待验证**（三选一，与 [爆量工场 BoostForge](../boostforge/EXECUTION-PLAN.md)、[通衢 RoadMind](../roadmind/EXECUTION-PLAN.md) 并列评估）

---

## 一、结论先行

**选题：高校学业-综测双目标路径规划智能体**

不做"校园问答机器人"，而是做**把学校制度文本变成每个学生可执行路径的那一层**。

### 一句话对比

| | 校园问答助手（常见做法） | **知途 PathPilot** |
|---|---|---|
| 核心难题 | **检索** —— 把答案找出来 | **规划** —— 把路径推演出来 |
| 产出 | 一段回答 | 一份可执行、可被真实结果修正的学期方案 |
| 会改主意吗 | ❌ 不会 | ✅ **会**（学期结果回流后自我修正） |

### 为什么这个痛点是真的（以及它有多真）

**先说实话：这个方向的经济痛点强度不如短剧投流。** 投流是"花钱如流水、ROI 可量化"；校园服务的价值不在省钱，在**减少信息不对称导致的决策损失**。

但损失是真实的、且高度集中：

- **选课**：学生一学期选 6-8 门课，主要依据是"问学长"和"零散评价"——信息极度碎片化。选错 = 一学期时间沉没 + GPA 受损。
- **综测**：直接影响**保研、国奖、评优**。国奖 8000 元/人，保研资格的长期价值远超此数。但综测细则复杂到**几乎没有学生完整读完过**——大量加分项（竞赛、志愿、职务、证书）学生**根本不知道存在**。
- **培养方案**：决定能否按时毕业、能否跨专业保研。但它是几百页 PDF，没人读。

> **一句话**：规则本来就是公开的，机会本来就存在。**Agent 消除的是信息不对称，不是制造分数。**

## 二、产品定义

### 产品定位

**「知途 PathPilot」** —— 面向高校学生的 **学业与综测双目标路径规划智能体**。

> "知途"取"明晰的路径"——学生缺的从来不是努力，是**不知道该往哪走**。

### 特定能力（答辩开场白）

> **读透一所学校的全部制度文本（培养方案 + 综测细则）与全部课程口碑，为每个学生算出一条「学业进度 × 综测得分」双目标最优的跨学期路径，并在每学期真实结果回流后自动修正这条路径。**

注意最后半句 —— **"会随真实结果修正"才是"特定能力"，"分析培养方案"只是功能。**

### 输入输出

| | 内容 |
|---|---|
| 输入 | 学生画像（培养方案版本 + 已修课程与成绩 + 综测历史 + 可投入时间）＋ 校本知识底座 |
| 输出 | ① 下学期选课方案（多套，含理由与风险）② 本学期综测行动清单与排期 ③ 学业预警与学习辅助 ④ 学期末偏差复盘报告 |

## 三、三类数据的处理：产品的地基

用户点名的三块能力，对应三层数据集：

| 数据 | 原始形态 | 处理成什么 | 支撑的功能 |
|---|---|---|---|
| **专业培养方案** | PDF / 教务系统网页，几十到几百页 | **课程知识图谱**：课程实体 + 先修关系 + 学分结构（必修/选修/通识/方向）+ 毕业要求映射 | 选课、学习辅助 |
| **课堂评价** | 教务评教文本，每课每年几十到几百条 | **课程/教师多维画像**：给分水平、**给分方差**、课业量、点名频率、考核方式、收获度 | 选课 |
| **综测细则** | 学生手册 / 学院文件，**各校各院不同、年年修订** | **结构化评分函数**：维度权重 + 加分项（分值 / 门槛 / 认定口径 / 申报窗口） | 综测自我提高 |

**三者的交叉才是价值所在**：培养方案告诉你"能选什么"，课堂评价告诉你"选了会怎样"，综测细则告诉你"为了什么选"—— **单独任一个都只是信息，合起来才是决策。**

## 四、技术架构：八工位流水线

```
【输入】学生画像 + 校本知识底座

⓪ 校本知识构建（离线批处理 · Token 消耗大户）
   · 培养方案 PDF      → 课程知识图谱
   · 课堂评价文本      → 课程 / 教师画像
   · 综测细则          → 评分函数 + 行动-分值表
   （全量重建规模：一所学校 × 全部专业 × 全部历史评价）
        ↓
① 学生状态解算
   毕业缺口（哪一类学分还差多少）｜ 先修链 → 下学期可选课程集 ｜ 综测各维度当前进度
        ↓
② ★ 目标与偏好推断（自主决策点 1）
   历史成绩 → 能力倾向 ｜ 时间预算 → 可承受课业量 ｜ 学生选择 → 价值取向（保研/出国/就业/稳 GPA）
        ↓
③ ★ 选课组合求解（自主决策点 2）
   多目标：毕业进度 + 预期 GPA + 综测增益 + 时间成本 − 给分方差风险
   硬约束：学分上下限 / 先修关系 / 必修课 / 时间冲突
   输出：帕累托前沿上的 K 套方案（"稳 GPA" / "冲综测" / "均衡"）
        ↓
④ ★ 综测行动规划（自主决策点 3）
   加分项反解为「行动-分值-成本-门槛-申报窗口」
   → 时间预算内的背包问题 → 排入学期时间轴（避开考试周）
   → ★ 学期中滚动追踪：周期性更新各维度进度，提示即将错过的申报窗口
        ↓
⑤ 学习辅助（贯穿）
   课程图谱 → 先修链补强、跨课程知识关联、"这门课怎么拿高分"（评价聚合）
        ↓
⑥ 方案呈现与理由生成
   每套方案：为什么这么排 / 风险在哪 / 需要放弃什么
        ↓
⑦ ★★ 学期回流与路径修正 ★★
   真实成绩 + 真实综测认定结果回流
   → 诊断偏差（预测给分 vs 实际、预期加分 vs 实际认定）
   → 修正先验（课程画像、加分认定口径）
        ↓
   回到 ①（闭环）
```

## 五、★ 为什么这是「智能体」而非工作流

这是评委最会追问的点。**自主决策点必须清晰可见：**

| 内核组件 | 自主决策内容 | 为什么不是工作流 |
|---|---|---|
| **目标推断器** | 自主判断这个学生到底要什么（保研？稳 GPA？补学分？） | 目标不是输入的，是**推出来的** |
| **选课求解器** | 自主在硬约束下搜索组合，产出多套帕累托方案 | 组合是**解出来的**，不是规则匹配 |
| **综测规划器** | 自主把细则反解成行动清单并排期 | 需要跨文档推理，非查表 |
| **★ 路径修正器** | **学期结果回流后自主修正先验与策略** | **会改变自己的行为** ← 最强自主性 |
| **反思校验器** | 方案违反先修/学分约束 → 自动重解 | 检查产出并重做 |
| **人工闸门** | 最终方案由学生确认；**价值取向由学生设定** | ★ 见下方 |

> **最后一行是这个方向的伦理底线**：Agent 可以算出"这样选综测更高"，但"要不要为了综测去水一门课"是学生的价值判断。
> **把价值选择留给人，把推演能力交给 agent** —— 这既是伦理要求，也恰好是"智能体"该有的边界。

> **一句话**：工作流不会改主意，**只有"会根据结果改变自己策略"的系统才是智能体。** 路径修正器就是那个东西。

## 六、★ 核心亮点：学期回流闭环

```
规划 → 选课 / 参加活动 → 学期结束 → 真实成绩 + 综测认定结果回流
  → 诊断偏差 → 修正课程画像与认定口径 → 下学期规划更准
```

**闭环的物理载体**：同一批学生、同一套课程，第 1 学期规划 vs 第 3 学期规划 —— **命中率曲线**就是价值证明。

### 与 BoostForge 的关键差异（也是本方向最大的结构性优势）

| | BoostForge | 知途 PathPilot |
|---|---|---|
| 回流数据 | 🔴 **拿不到**（无投放预算）→ 只能靠离线回放/模拟器 | ✅ **真的拿得到**（成绩单 + 综测认定） |
| 用户 | 投流团队（团队不懂投流） | ✅ **团队自己就是用户** |
| 迭代周期 | 素材 3-7 天衰减（快，但需持续投放） | **一学期一轮**（慢，但真实且必然发生） |

> ⚠️ **但迭代周期慢是双刃剑**：一个学期才回流一次，比赛周期内**最多只有 1-2 次真实回流**。这是本方向必须正面处理的弱点，对策见第八节「历史学期回放」。

## 八、商业落地：为什么移动云会想要这个

| 维度 | 说明 |
|---|---|
| **客户就是移动云的客户** | 高校是运营商云 ToB/ToG 的主战场（智慧校园、教育云）。**移动云本就在卖高校信息化**，本产品可挂进现有产品线 |
| 谁付费 | **学校（教务 / 学工部门）付费，学生免费使用** —— B2B2C，付费方与使用方分离，而学校有动力买（就业率 / 保研率 / 学生满意度是学工 KPI） |
| 可复制性 | 培养方案与综测细则**校校不同** —— 这既是壁垒（换学校要重建底座），也是**天然的续费理由**（每年细则修订就要重新构建） |
| Token 消耗 | 一校一底座，全量重建是**亿级 Token** 的批处理；每届新生入学即触发一次全量 |

> 对比 BoostForge：短剧投流团队属抖音生态，**未必是移动云的客户**。本方向的付费方与云厂商客户群完全重合。

## 九、评测体系

| 维度 | 指标 | 方法 |
|---|---|---|
| 解析质量 | 培养方案 → 课程图谱的抽取准确率 | 人工标注 3 个专业做金标准 |
| 画像质量 | 课程给分预测 vs 实际给分的 MAE | 回归指标（留出学期验证） |
| 规划质量 | 推荐方案的综测得分 vs 学生自主选择的综测得分 | 对照实验 |
| **★ 学习效果** | **迭代 N 轮后规划命中率的提升幅度** | **核心指标** |
| 效率 | 选课规划耗时 vs 人工（问学长 + 翻文件） | 耗时对比 |
| 合规 | 敏感数据不出域 | 架构审计 |

### ★ 三组对照实验（最有说服力的部分）

| 方案 | 选课依据 | 综测结果 |
|---|---|---|
| 无辅助（问学长 / 凭感觉） | 基准 | 基准 |
| 静态推荐（只用评价数据，**不学习**） | 中 | 持平或略好 |
| **Agent 带学期回流学习** | **高** | **显著提升** |

> **第三行就是全案的价值证明。**

### 轮次不足的对策（必须正面写进报告）

比赛周期内真实回流只有 1-2 次，因此采用**历史学期回放**：拿往届同专业学生的成绩与综测轨迹做离线迭代，让"第 1 轮 vs 第 N 轮"在报告期内可观测。

> **学术上这叫「离线评估」，与 BoostForge 的离线回放是同一套方法论。**
> **关键：如实说明数据来源与轮次限制** —— 藏不住，且诚实说明反而是加分项。

## 十、合规与伦理（本方向必须单独成章）

| 议题 | 风险 | 对策 |
|---|---|---|
| **个人数据** | 成绩 / 评教 / 综测记录是敏感个人信息 | 机密模型服务；数据不出校；学生自主授权；**可撤回** |
| **评教匿名性** | 评教原文本可反向定位教师 | **只输出聚合画像，绝不出原文**；小样本（< N 条）不出画像 |
| **功利化争议** | "优化综测"易被视为"教学生刷分" | 定位为**信息对称化**：规则公开、机会公开，agent 只做推演。**价值取向由学生设定，agent 不预设** |
| **学术诚信** | 选课建议不应鼓励"水课刷 GPA" | 把"课程对能力链的价值"也作为目标之一；**多方案并列而非单一最优** |
| **教师声誉** | 给分 / 课业量画像可能伤害教师 | 只校内可见；不做跨校排名；不下"好/坏老师"结论，只给客观维度 |

> ★ **这一章不是减分项，是加分项** —— 它证明团队想清楚了"这东西落到真学校要过哪几关"。而这几关，恰好每一关都指向 MoMA 的能力。

## 十一、团队分工（4 人）

| 角色 | 职责 | 关键交付 |
|---|---|---|
| **P1 · 队长 / 产品 + 教务业务** | 培养方案与综测细则的业务理解、方案设计报告、答辩主讲、**组委会赛道挂靠沟通**、进度管理 | 设计报告、答辩 PPT |
| **P2 · 后端 / 架构** | MoMA 网关、八工位编排、**知识底座构建管道**、选课求解器工程实现 | 编排层、数据管道 |
| **P3 · 算法 / 规划与学习** | 课程图谱抽取、教师画像、**多目标选课求解**、**综测行动规划**、**路径修正器**、评测体系 | 求解器、修正器、评测报告 |
| **P4 · 前端 / 全栈** | 学业路径看板、选课方案对比、综测进度条、学期复盘报告、AI Store 材料 | 前端产品、上架材料 |

### 关键路径

```
P3 图谱抽取 + 多目标求解 + 路径修正 ──┐
   (技术命门，最先启动)               │
                                      ├──→ 闭环验证 → 对照实验 → 材料
P2 编排 + 底座构建管道 ───────────────┤
                                      │
P4 前端路径看板 + 复盘报告 ───────────┘

P1 教务业务 + 报告 + 答辩 ── 全程并行
```

### 三条铁律（沿用）

1. **P3 最先动工**（多目标求解与路径修正是技术命门）
2. **P2 与 P4 先冻结接口**再各自开工
3. **P1 不参与编码**，专注业务与答辩

> **⚠️ P1 的技能要求（这是本方向相对 BoostForge 的显著优势）**：不需要补外部专业知识 —— **P1 自己就是大学生，这个方向的领域知识是"在场"的**。

## 十二、里程碑

> 时间未定，按 10 周标准档；压缩到 6 周时砍掉：⓪ 全量底座重建（只做 2-3 个专业）、历史学期回放、部分画像维度。

### Phase 0 · 启动与澄清（T0 + 0~1 周）
- ★ **向组委会确认赛道挂靠**（高校服务是否计入"智能协同办公"）← **硬阻塞，最先做**
- 拿到 3 个专业的培养方案 + 1 份综测细则 + 1 门课的评教数据
- **交付**：选题冻结 **或** 放弃本方向

### Phase 1 · PoC 验证（T0 + 1~3 周）
- 培养方案 → 课程图谱跑通（3 个专业）
- 1 门课的教师画像跑通
- 综测细则 → 评分函数跑通，**并让一个学生手算验证**
- **交付**：PoC Demo + 解析准确率基线报告

### Phase 2 · 核心开发（T0 + 3~6 周）
- 八工位流水线、选课求解器、综测行动规划器
- 学业路径看板 + 综测进度追踪
- MobileClaw Skills 集成
- **交付**：可运行产品 v1

### Phase 3 · 闭环验证与评测（T0 + 6~8 周）
- **历史学期回放**：往届学生轨迹离线迭代，记录命中率提升曲线
- 小范围真实用户试用（本校同学，1-2 个专业）
- 三组对照实验完整数据

## 十三、风险与对策

| 风险 | 影响 | 对策 |
|---|---|---|
| **赛道挂靠不被接受** | **极高** —— 跑题即出局 | **Phase 0 第一件事，直接问组委会**；备选叙事：把重心移到"制度文档的智能协同"（智能协同办公的本义） |
| **痛点烈度不如短剧投流** | 高 —— 评委可能觉得"不痛" | 锚定**保研 / 国奖**这类可量化高价值结果；量化信息不对称的代价（学生多花多少时间、错过多少加分项、多少人根本没读过细则） |
| **学期回流轮次不足** | 中 —— 闭环说服力弱 | 历史学期回放补轮次；如实说明限制 |
| **演示冲击力弱** | 中 —— 没有"素材墙"那种视觉 | "第 1 学期 vs 第 N 学期规划对比" + 综测进度可视化 + **真实同学的前后对比** |
| 冷启动：新课 / 新教师无评价 | 中 | 课程属性相似度迁移；标注置信度 |
| 综测加分认定主观 | 中 | 官方口径 + 置信度标注；**只承诺信息完备，不承诺分数** |
| 评教样本偏少 | 中 | 小样本不出画像；多学期累积 |
| **撞题（校园问答机器人）** | 中 | 差异化不在问答，在**跨学期规划闭环**；答辩明确切分 |

## 十四、★ 验证清单（当前最高优先级）

> **方向是否可行，不取决于再选多少次，而取决于验证。**

| # | 动作 | 验证什么 | 若失败的后果 |
|---|---|---|---|
| **1** | **问组委会：高校服务场景是否计入「智能协同办公」赛道** | 会不会跑题 | **硬阻塞，方向直接作废** |
| **2** | 拿 3 个专业的培养方案 PDF，解析成课程图谱 | 底座能不能建 | 是地基，失败则产品不成立 |
| **3** | 拿 1 份综测细则，结构化成分数函数，**让一个学生手算验证** | 细则能不能被工程化 | 硬核模块失败 → 降级为"选课 + 学习辅助" |
| **4** | 拿 1 门课 50+ 条真实评价，聚合出有区分度的教师画像 | 画像有没有信息量 | 选课推荐质量存疑 |
| **5** | 找 5 个同学，问"你愿意用吗？愿意为哪个功能用？" | 真实需求强度 | 痛点假设被证伪 |

**第 2-5 项一周内可完成。第 1 项一天即可，且它决定其余要不要做。**

## 十五、与 BoostForge 的对比与建议

### 逐项对比

| 维度 | 爆量工场 BoostForge | 知途 PathPilot | 谁更优 |
|---|---|---|---|
| **赛道匹配** | ✅ 明确属于高 Token 场景（AI短剧） | ⚠️ 需挂靠"智能协同办公"，**有跑题风险** | **BoostForge** |
| **命门失败后作品成立？** | ✅ 成立（仍是素材工厂） | ✅ 成立（仍是选课 + 学习助手） | 平 |
| **回流数据可得性** | 🔴 **拿不到**（最大风险） | ✅ **拿得到**（成绩 + 综测认定） | **PathPilot** |
| **领域知识可得性** | ⚠️ 需外部补课（投流业务） | ✅ **团队在场**（自己就是学生） | **PathPilot** |
| **真实用户可得性** | ⚠️ 需找投流团队 | ✅ **同学就在身边** | **PathPilot** |
| **Token 消耗论证** | ✅ 天然黑洞（视频生成） | ⚠️ 需靠"全校全量"规模堆 | **BoostForge** |
| **演示冲击力** | ✅ 素材墙，视觉强 | ⚠️ 曲线与表格 | **BoostForge** |
| **痛点烈度** | ✅ 买量占收入 70-80% | ⚠️ 中等，但集中在保研 / 国奖 | **BoostForge** |
| **商业落地（移动云视角）** | ⚠️ 客户未必是移动云客户 | ✅ 高校就是移动云 ToB 客户 | **PathPilot** |
| **撞题风险** | ✅ 低（"素材进化闭环"少见） | ⚠️ 中（校园助手常见，**闭环少见**） | **BoostForge** |

### 这是一次「用赛道风险换执行风险」的交换

- **BoostForge 的风险集中在「钱和资源」** —— 拿不到投放数据、找不到懂投流的人、Token 配额可能不覆盖视频模型。**这些都不是团队努力能解决的。**
- **PathPilot 的风险集中在「评委的接受度」** —— 一个赛道挂靠问题 + 一个痛点烈度问题。**这两个都是"沟通"问题，不是"资源"问题。**

### 具体建议

1. **先用一天回答验证清单第 1 项**（问组委会）。若高校服务被拒 → 本方向作废，BoostForge 继续，代价仅为一天。
2. **若被接受**，这是一个**执行确定性显著高于 BoostForge** 的方向 —— 数据在手、用户在手、领域知识在手，能在比赛周期内做出**真正跑通的闭环**。
   你们仓库里那句话同样适用于这里：**"完成度高的中等作品，永远赢过完成度低的高远作品。"**
3. **不建议两条线并行** —— 4 人团队做两个方向，两个都会停在 60% 完成度。
