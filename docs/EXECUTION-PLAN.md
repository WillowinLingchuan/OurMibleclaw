## 一、结论先行

**选题：金融 × AI视频巡店（银行网点智能巡检与合规处置闭环）**

不是"用一个模型看视频"，而是**用 MoMA 的多模型调度把一次巡检拆成"感知 → 判定 → 处置 → 复核"四个智能体**，让智能路由和 Token 集约化成为**架构刚需**而非演示装饰。

### 为什么是"金融 × 视频巡店"，而不是其他组合

| 候选 | Token 消耗 | MoMA 路由是否刚需 | 演示冲击力 | 业务闭环 | 判断 |
|---|---|---|---|---|---|
| **金融 × AI视频巡店** | 极高（视频帧多模态） | **是**（多模态+OCR+推理+语音天然异构） | 强（视频直观） | 完整（发现→派单→整改→复核） | ✅ **主选** |
| 金融 × 智能协同办公 | 中 | 弱（基本一个长文本模型够用） | 弱（文档类同质化严重） | 中 | ⚠️ 备选 |
| 金融 × AI编程 | 中 | 弱 | 弱 | 弱 | ❌ |
| 金融 × AI短剧（反诈） | 高 | 中 | 强 | 弱（生成即终点） | 💡 差异化备选 |
| 金融 × AI终端 | 高 | 中 | 依赖硬件 | 中 | ❌ 硬件成本 |

**核心理由**：视频巡检是唯一一个「赛道要的高Token消耗」与「MoMA路由价值」同时成立的场景——同一个摄像头画面，普通帧该用便宜模型、可疑帧该用强模型，**这个决策点天然存在的场景，才讲得清智能路由的价值**。

## 二、赛事约束解读（含必须澄清的风险）

### 已核实的约束

1. **赛道按场景划分，不按行业划分**
   应用赛道只收五类高 Token 消耗场景：`AI编程` / `AI短剧` / `智能协同办公` / `AI视频巡店` / `AI终端`。
   → **"金融"必须挂靠到"AI视频巡店"之下**，方案叙述必须以"视频巡店"为第一身份，"金融行业"为垂直深化。

2. **作品需基于 MoMA 平台支持 Token 调用**
   → 必须实际调用 MoMA 统一 API 网关，而非自建推理。

3. **作品需可上架移动云 AI Store 平台**
   AI Store 正式商业上架的资质要求是：**营业执照 + 一般纳税人证明 + 银行开户信息**。
   → **学生团队无法走完商业上架。** 因此交付目标应修正为：
   **"达到可上架标准 + 提交完整上架材料包"**（产品说明书、接口文档、定价与 Token 组合售卖方案、审核所需材料清单）。
   这一点建议**提前向组委会书面确认**，避免答辩时被质疑。

4. **赛事提供的资源**
   百万级现金奖励、万亿 Token 资源、通算资源、模型接入绿色通道、总决赛在移动合作伙伴大会期间举办。

## 三、项目定义

### 产品定位

**「巡鹰 GuardEye」** —— 面向银行/保险网点的 **7×24 智能巡检与合规处置闭环智能体**。

替代传统"人工看监控 + 事后抽查"，实现：

```
摄像头视频流
    ↓
[巡检Agent] 抽帧 + 多模态理解 → 发现异常事件
    ↓
[判定Agent] 规则库 + 文本推理 → 风险定级（高/中/低）
    ↓
[处置Agent] 生成工单 + 派发 + IM通知 → MobileClaw Skills 承接
    ↓
[复核Agent] 整改后回看 + 验收 → 闭环归档
    ↓
数据看板：事件趋势 / 整改率 / Token成本 / ROI
```

### 巡检事件类型（首版收窄到 6 类，保证准确率）

| 事件 | 价值 | 依赖能力 | 风险级 |
|---|---|---|---|
| 双人临柜/双人加钞未执行 | 监管硬性要求 | 视觉+时序推理 | 高 |
| 消防通道堵塞 | 安全检查 | 视觉识别 | 高 |
| 员工着装/工牌不规范 | 服务规范 | 视觉+OCR | 低 |
| ATM 区域异常滞留 | 安全预警 | 时序行为分析 | 中 |
| 客户排队时长超阈值 | 服务体验 | 时序统计 | 中 |
| 柜台单据/凭证识别归档 | 效率提升 | OCR+文本理解 | 低 |

> 每类事件标注"风险等级"，**风险等级直接驱动模型选型** —— 这是智能路由的决策依据。

### ★ 智能路由策略设计（方案的技术核心）

把**风险等级**作为路由的决策变量，这是一条真实可验证的策略链：

| 触发条件 | 路由策略 | 模型档位 | 理由 |
|---|---|---|---|
| 常规帧 / 低风险规则（着装、排队） | **成本优先** | 普惠档（轻量多模态） | 量大、容错高，用便宜模型 |
| 可疑帧 / 高风险规则（双人临柜、加钞） | **效果优先** | 精品档（强多模态） | 漏报代价极高，必须用最强模型 |
| 单据识别、报告生成 | **均衡优先** | 中间档 | 准确率与成本平衡 |
| 涉客户隐私画面（面客区） | **机密模型** | 机密容器 | "可用不可见"，硬件级隔离 |

> **可量化的论点**：假设 95% 的帧是常规帧，路由到便宜模型可将整体 Token 成本压降 60%+（需实测验证），且高风险事件的召回率**不下降**。这个实验数据是本方案最有说服力的部分。

## 五、竞争策略：凭什么能赢

多数参赛队会犯的错误是：**调一个大模型 + 套个壳 + 做个界面**。本方案的差异化在四个点：

1. **把平台能力用成"刚需"而非"装饰"**
   我们不写"我们使用了智能路由"，而是给出**对照组实验**：
   `全量走强模型` vs `全量走弱模型` vs `按风险分级路由`
   三方对比 **成本 / 准确率 / 召回率 / 时延** 四维数据 → 用数据证明平台价值。

2. **成本叙事可量化**
   视频是高 Token 场景，"Token 压缩 + 智能缓存"带来的降幅最容易做出漂亮数字。
   输出：`单网点/天 Token 消耗`、`接入 MoMA 后成本降幅`、`每万元巡检成本的 ROI`。

3. **业务闭环而非单点识别**
   绝大多数队伍止步于"识别出异常"。我们做到 **发现 → 定级 → 派单 → 整改 → 复核 → 归档** 全闭环，且用 MobileClaw 的既有 Skills 承接，产品成熟度直接高一个档次。

4. **合规与安全是真卖点**
   金融行业对"数据上云、上模型"极度敏感。MoMA 机密模型服务的"可用不可见"是**真实的合规解法**，不是营销词——这能直接回应评委的隐私质疑。
