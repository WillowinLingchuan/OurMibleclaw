## 一、结论先行

**选题：AI短剧工业化流水线（微短剧批量生产 Agent）**

不做"一个视频生成工具"，而是做**一条产线**：把短剧生产拆成 9 个工位，每个工位由不同智能体 + 不同模型承担，用 MoMA 的智能路由控成本、用上下文管理保证**角色一致性**和**跨集剧情连贯**。

### 为什么这条赛道比巡检更干净

| 维度 | 金融 × 巡检 | **AI短剧** |
|---|---|---|
| 赛道归属 | ⚠️ 金融是行业，需挂靠"视频巡店"，**有被驳回风险** | ✅ **直接命中，零归属风险** |
| 数据可得 | 差（银行视频拿不到） | ✅ **不需要企业数据，剧本自创** |
| 演示效果 | 强 | ✅ **作品本身就是演示** |
| 商业模式 | 中 | ✅ **纯 Token 消耗型服务，完美契合"Token 组合售卖"** |
| 平台能力承重 | 高 | ✅ **更高（上下文管理成为头号技术难题）** |

> **关键洞察**：AI Store 的合作模式是"深度融合移动云底层资源 + **叠加移动云Token组合售卖**"。短剧生成按"每集消耗多少 Token"计价，是**最纯正的 Token 生意** —— 赛道要"高 Token 消耗场景"，这条赛道本身就是。

## 二、这个方向真正难在哪（也是我们的机会）

微短剧行业 2025-2026 爆发式增长，但 AI 生产有个**公认的头号难题**：

> **角色一致性** —— 同一个角色在 100 个分镜里不能长成两个人。
> **剧情连贯性** —— 第 80 集的主角，必须记得第 37 集发生过什么。

**这两点恰好是"上下文管理"的教科书级应用场景**，比巡检里的帧缓存有意义得多。绝大多数参赛队会做出"输入一句话 → 输出一段视频"的玩具；我们要做的是**解决行业真痛点的产线**。

而**多模型调度**在这里是硬需求，不是选择：

| 工位 | 需要的模型类型 |
|---|---|
| 剧本/对白 | 强文本模型 |
| 分镜拆解 | 多模态理解模型 |
| 角色定妆图 / 场景概念图 | 文生图模型 |
| 正片生成 | **文生视频模型** |
| 配音 | 语音合成模型 |
| 内容合规审核 | 内容安全模型 |
| 出海多语言 | 多语言模型 |

**七类模型，一次网关接入** —— 这就是 MoMA 存在的理由，不需要我们牵强论证。

## 三、项目定义

### 产品定位

**「千幕 DramaForge」** —— 面向短剧制作公司的 **AI 短剧工业化生产流水线**。

输入：题材方向 + 人设要求
输出：可直接进入后期的**成片 + 全套素材**

### 适用范围（必须收窄，这是可行性关键）

❌ **不做**：古装、战争、特效、复杂动作、多人打斗、需要文字渲染的镜头
✅ **做**：**都市情感 / 悬疑对话剧** —— 人物对话为主、场景简单（室内、街道）、镜头以中近景和对话正反打为主

> 这不是偷懒，**这是真实短剧工厂的做法**。约束题材范围是控制生成质量与成本的标准工程手段，答辩时主动说明反而加分。

### 交付范围

| 项 | 内容 |
|---|---|
| 完整成片 | **1 集（60-90 秒）** 端到端跑通 |
| 片段证明 | 3-5 集片段，证明跨集剧情记忆与角色一致性成立 |
| 产线证明 | 批量任务编排界面 + 成本/产能看板 |

> 不可能做 60 集。**"1 集完整 + 跨集片段 + 可扩展架构"** 是唯一现实且有说服力的交付形态。

## 四、技术架构

### 九工位流水线

```
① 立项策划     题材/人设/大纲        → 强文本模型
        ↓        产出: 角色档案(Character Bible) + 分集梗概
② 剧本生成     分集剧本/对白         → 强文本模型 + 剧情状态机
        ↓        产出: 分集剧本 + 场景表
③ 分镜拆解     镜号/景别/画面/对白    → 文本 + 多模态
        ↓        产出: 分镜表(Storyboard)
④ 视觉资产     角色定妆图 + 场景图    → 文生图模型 ★角色档案注入★
        ↓        产出: 角色参考图库 + 场景素材库
⑤ 草稿预览    低分辨率关键帧/短片段   → ★成本优先路由★ 便宜快速模型
        ↓        产出: 分镜预览 → 确认构图与节奏
⑥ 正片生成    视频片段              → ★效果优先路由★ 强文生视频模型
        ↓        产出: 视频片段 + ★一致性反查闭环★
⑦ 后期合成     配音/字幕/配乐/剪辑    → 语音合成模型 + 剪辑
        ↓        产出: 成片
⑧ 合规审核     内容安全审查          → 内容安全模型
        ↓        不通过 → 生成重做工单 → 回退⑤/⑥
⑨ 出海适配     多语言配音/字幕        → 多语言模型（可选加分项）
```

### ★ 核心亮点一：角色一致性引擎（上下文管理的主战场）

这是本方案**最难、也最值钱**的部分。单靠模型做不到，必须工程化：

```
角色档案 (Character Bible) — 结构化定义
  ├─ 外貌: 年龄/脸型/发型/发色/瞳色/体型
  ├─ 服饰: 标志性服装、配饰
  ├─ 性格: 语气、口头禅、常用表情
  └─ 参考图: 一张锁定的"定妆照"

        ↓ 固定注入每一次生成（模板化拼装，禁止自由发挥）

① 提示词模板化   所有分镜的角色描述从档案自动拼装
② 参考图锚定      image-to-video / 参考图条件生成
③ 种子控制        固定 seed 提升稳定性
④ ★一致性反查闭环★  生成后用多模态模型反向提问:
                   "画面中的人物是否是【角色A】的同一人？"
                   → 不一致 → 自动重生成（最多N次）→ 仍不一致则转人工
⑤ 量化评分        face embedding 余弦相似度，输出一致性分数
```

> **④ 是最能打动评委的设计** —— 它让"多模态模型"成为**质检员**，形成"生成 → 自检 → 重做"的 Agent 闭环。这不是调 API，这是智能体。

### ★ 核心亮点二：剧情状态机（Token 压缩的落地点）

100 集剧本不可能全塞进上下文。解法：

```
剧情状态机 (结构化 JSON)
  ├─ 人物关系图（当前进展到哪一步）
  ├─ 已知信息表（谁在第几集知道了什么）
  ├─ 伏笔清单（埋了什么、还没回收什么）
  └─ 时间线
```

- 每集生成后**增量更新**状态机
- 生成第 N 集时，注入 **"前情摘要 + 当前状态"**，而非全部剧本
- **这就是 MoMA 的 Token 压缩与上下文复用在真实业务中的落地** —— 100 集剧本压缩成结构化状态，Token 消耗从 O(N) 降到 O(1)

### ★ 核心亮点三：智能路由策略（成本可控的关键）

| 阶段 | 路由策略 | 模型档位 | 理由 |
|---|---|---|---|
| ⑤ 草稿预览 | **成本优先** | 普惠档（便宜/快速） | 只为确认构图节奏，废稿率极高，用便宜模型 |
| ⑥ 正片生成 | **效果优先** | 精品档（最强） | 定稿质量决定成片，不能省 |
| ② 剧本 ③ 分镜 | **均衡优先** | 中间档 | 质量与成本平衡 |
| ④ 场景概念图 | **智能缓存** | 复用已有素材 | **同场景多镜头复用，视频生成最贵，缓存收益最大** |
| ⑧ 合规审核 | **均衡优先** | 内容安全模型 | 必须可靠 |

**可量化论点**：草稿阶段废稿率若为 70%（真实短剧行业合理假设），把这 70% 的生成量路由到便宜模型，可将整体 Token 成本压降 **50%+**，且**成片质量不下降**（因为定稿仍走最强模型）。这个对照实验是本方案最有说服力的数据。

## 五、竞争策略：凭什么能赢

大多数队伍会做出"输入一句话 → 输出一段视频"的玩具。我们的差异在四点：

1. **解决的是行业公认头号难题**
   不回避角色一致性，而是正面攻坚并给出**可量化的分数**（face embedding 相似度）。评委一看就知道我们懂这个行业。

2. **"生成 → 自检 → 重做"的 Agent 闭环**
   用多模态模型当质检员，这是**真正的智能体设计**，而不是 API 串联。

3. **成本叙事可量化，且契合赛道定位**
   短剧是**最贵的 Token 消耗场景**（视频生成），所以路由与缓存的降本幅度也是最大的。
   输出：`每集成片 Token 成本`、`草稿/定稿分级路由的降本幅度`、`产能对比（人工 vs 流水线）`

4. **产品化完备度高，天然适合上架**
   短剧生成是纯 Token 消耗型服务，完美契合 AI Store"叠加 Token 组合售卖"模式。商业模式一页纸讲清：**按集计价 / 按 Token 后付费 / 素材库增值**。

## 八、评测体系（决定答辩说服力）

| 维度 | 指标 | 方法 |
|---|---|---|
| **角色一致性** | face embedding 余弦相似度 | 自动计算，输出分数分布 |

### ★ 三组对照实验（最有说服力的部分）

| 方案 | Token 成本 | 角色一致度 | 成片可用率 |
|---|---|---|---|
| 全流程走强模型 | 基准（最高） | 高 | 高 |
| 全流程走弱模型 | 最低 | **低** | **低** |
| **分级路由**（草稿弱 + 定稿强 + 缓存复用） | **低** | **高** | **高** |

> 用四维数据证明：**分级路由在成本上接近全弱模型，在质量上接近全强模型。** 这就是 MoMA 智能路由的量化价值。
