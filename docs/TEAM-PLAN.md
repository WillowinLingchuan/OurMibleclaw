# 千幕 DramaForge · 难度评估与团队分工

> 配套文档：`EXECUTION-PLAN-SHORT-DRAMA.md`（执行方案）、`FEATURE-SPEC.md`（功能规格）

# 第一部分：制作难度评估

## 总体评级：★★★★☆（偏高，但不是"做不到"）

**关键区分：这个项目的技术栈不前沿** —— 全部是 API 编排和工程集成，没有需要发论文的东西。

**难的不是"写代码"，是"控制质量"和"控制成本"。**

## 逐模块难度

| 模块 | 难度 | 说明 |
|---|---|---|
| MoMA 网关封装 | ★☆☆☆☆ | 就是 HTTP 调用，一天的事 |
| 剧本 / 分镜生成 | ★★☆☆☆ | 提示词工程，能出活，出好活要磨 |
| 内容安全审核 | ★★☆☆☆ | 调 API |
| 前端工作台 | ★★★☆☆ | 不难但**工程量大**，吃掉大量时间 |
| 剧情状态机 | ★★★☆☆ | 结构化设计，想清楚就不难 |
| 后期剪辑合成 | ★★★☆☆ | ffmpeg 现成方案 |
| 视频生成接入 | ★★★☆☆ | 接口简单，**成本控制要命** |
| 成本路由优化 | ★★★★☆ | 需要大量对照实验调参 |
| 一致性反查闭环 | ★★★★☆ | 涉及阈值调优、重试策略 |
| **角色一致性** | **★★★★★** | **最难，且是行业未解难题** |

## 真正的三个杀手

### 🔴 杀手一：Token 配额烧完

视频生成是最贵的模态。要反复试错，**每次试错都在烧钱**。四人团队两个月，如果草稿阶段不做成本分流，配额可能第一周就烧掉一半。

> **这是最现实的死法，而且死得无声无息。**

### 🔴 杀手二：角色一致性做不出来

这不是"努努力就能解决"的问题 —— **它是行业公开难题，商业公司也没完全解决**。能做的是**工程缓解**（档案 + 参考图 + seed + 反查重做），不是根治。

如果一致性只有 60 分，**"特定能力"就不成立，整个作品的立论基础塌了**。

### 🔴 杀手三：成片质量差

生成出来如果"一眼假"，演示视频会非常尴尬。**评委不看架构多漂亮，先看产出能不能看。**

## 难度结论

| 交付目标 | 4 人所需时间 | 可行性 |
|---|---|---|
| **最小可信闭环**（1 集跑通、一致性达标） | 4-6 周 | ✅ 可行 |
| **完整产品**（9 工位 + 看板 + 批量） | 10-12 周 | ⚠️ 偏紧，需顺利 |
| **完整产品 + 出海 + 模板市场** | 16 周+ | ❌ 不建议 |

**判断：这是一个"做出来不难，做好很难"的项目。** 决定成败的不是功能数量，是**角色一致性这一件事做到什么程度**。

# 第二部分：四人分工方案

## 分工原则：不平均切四份，按「风险」切

**最多的人力必须压在最长的那根钉子上（一致性）。**

其他模块做不完美只是减分，**一致性做不出来是直接出局**。

## 四个角色

### P1 · 队长 / 内容与产品

**定位：内容质量第一责任人 + 对外接口**

| 负责方向 | 具体内容 |
|---|---|
| 内容侧 | 题材策划、世界观、角色设定、剧本创作、分镜内容把关 |
| 产品侧 | 产品设计报告撰写、需求定义 |
| 交付侧 | 答辩主讲、路演、演示视频脚本 |
| 管理侧 | 进度管理、**组委会问询（最优先）** |
| 运维侧 | 素材库运营、成片剪辑合成 |

> **为什么是他**：内容和答辩是全队的"出口"，产品报告与答辩占比很高，必须有专人吃透。
> **⚠️ 注意**：队长别去写代码抢 P3 的活 —— **内容质量的天花板就是项目天花板**。

---

### P2 · 系统架构 / 后端

**定位：产线骨架的搭建者**

| 负责方向 | 具体内容 |
|---|---|
| 网关 | MoMA 统一网关封装（7 类模型接入） |
| 编排 | 九工位流水线编排引擎、状态流转 |
| 路由 | **智能路由决策器**（成本优先 / 效果优先 / 均衡优先） |
| 调度 | 批量任务队列、失败重试、**模型故障自动切换** |
| 计量 | Token 成本计量与看板数据接口 |

> **为什么是他**：这是全系统的"血管"。MoMA 的差异化能力（路由、切换、计量）**全部落在这个人手上**。
> **技能要求**：后端工程能力，熟悉异步任务、状态机。

---

### P3 · 算法 / 一致性 ★★★ 技术命门

**定位：全队风险最高、最该先动工的一环**

| 负责方向 | 具体内容 |
|---|---|
| **一致性引擎** | 角色档案结构、参考图链路、seed 与提示词策略 |
| **反查闭环** | 多模态校验 + embedding 相似度 + 阈值 + 重试策略 |
| 提示词工程 | 分镜 → 画面描述的模板化拼装 |
| 评测体系 | **三组对照实验**设计、指标计算 |
| 模型选型 | 哪类镜头用哪个模型、哪档服务 |

> **为什么是他**：**这是项目命门。这个人弱，全盘皆输。**
> **技能要求：必须全队最强**，熟悉多模态模型、embedding、实验设计。
> **⚠️ 他必须第一个动工**（Phase 1 就要验证一致性），不能等骨架搭好。

---

### P4 · 前端 / 全栈

**定位：把能力变成"能用"的产品**

| 负责方向 | 具体内容 |
|---|---|
| 工作台 | 分镜编辑、草稿预览确认、单镜头重生成 |
| 看板 | 成本与产能可视化、路由分布、一致性分数分布 |
| 素材库 | 角色图库、场景库管理界面 |
| 上架 | AI Store 上架材料与对接 |

> **为什么是他**：评委和用户**只看得到前端**。后端再优雅，界面难用就是"没做完"。
> **⚠️ 注意**：前端工作量被低估是常态，**给他留足时间**。

---

## 关键路径

```
P3 角色一致性 ──────────────┐
   (最先启动，风险最高)      │
                            ├──→ 集成 → 成片 → 演示
P2 骨架/编排 ───────────────┤
   (P3 验证通过后并行铺开)   │
                            │
P4 前端工作台 ──────────────┘
   (可与 P2 并行，接口先约定)

P1 内容/报告/答辩 ── 全程并行，Phase 4 收口
```

### 三条铁律

1. **P3 必须先动工**，其余人可以稍后
2. **P2 和 P4 先约定接口**，再各自开工（避免联调地狱）
3. **P1 不参与编码**，否则没人盯内容和答辩

---

## 协作机制

> 四人队最容易死在沟通上。

| 机制 | 频率 | 内容 |
|---|---|---|
| **接口冻结** | 第一周内 | P2 ↔ P4 约定 API 契约，之后改动走流程 |
| **站会** | 每天 15 分钟 | 各自进度 + 卡点 |
| **周集成** | 每周五 | 必须合入一次可运行版本，**禁止"我本地能跑"** |
| **风险通报** | 随时 | P3 一旦发现一致性做不动，**立刻全队转向** |

### 降级预案

若 P3 验证下来角色一致性无法达标 → **退守"单集内一致性"叙事**，仍可立住作品，但必须立即全队转向，不要硬扛。

---

## 人员配置建议

按重要性排序找人：

1. **P3 算法** —— 最关键，**找不到合适的人就别做这个方向**
2. **P2 后端** —— 骨架搭不起来什么都白搭
3. **P4 前端** —— 决定作品"看起来的完成度"
4. **P1 内容/产品** —— 最容易补，但别随便找

> **淘汰线**：如果四个人里没有一个能扛 P3，建议**换成连锁门店巡检方向** ——
> 那个方向没有"角色一致性"这种命门级难题，技术风险低一个数量级。

## 变体方案

### 实际只有 3 人

- **P1 与 P4 合并**（队长兼前端）
- 砍掉出海适配与模板市场
- **P2 和 P3 绝不能合并** —— 这两个是全队的技术主干

### 实际有 5 人

- 拆出独立的 **评测与成本优化** 岗，专做三组对照实验与 Token 成本分析
- 这是我方拉开差距的最大差异点，值得专人负责
